# CI精简与完整发布实测（2026-10-11）

## 目标和最终形态

实现基线`8bea4c5`已合入main。最后完整增量发布4分56.2秒，广范围发布5分14.8秒；两种范围分别保留。

在保留原检查范围、断言、超时、一次用例重试、完整业务数据交接和精确SHA门禁的前提下，减少重复准备和CI编排。最终采用一个workflow：plan、一个core、固定6个browser分片、verify，共9个作业；main已有同SHA／基线的成功候选时，只执行轻量plan核对。直接推送main、证据不匹配或证据缺失时仍执行完整所选检查，计划失败也不能跳过聚合门禁。

浏览分片各用独立主机、独立fixture测试库、1个worker；每片只安装一次依赖与Chromium、迁移和seed一次、启动一个受控Next服务并预热一次。所选旅程／E2E／视觉套件串行共用服务，浏览上下文和报告独立。保留输入漂移、fixture租约、进程树清理、失败协同取消及取消确认。无可复用任务的浏览检查缓存已移除。

## 重复准备与失败恢复

- **构建指纹**：独立release先加载与push相同的本地环境声明。进一步复现pnpm每嵌套一层将相同NODE_PATH从3条追加为6／9条，只有3个唯一路径；旧指纹因此不同。现在按平台分隔符去重并保留首次出现顺序，真实路径、顺序及其他环境变化仍使证据失效。本机发布已实际输出同一已验证产物复用记录。静态预检从约9.5秒降至约1.7–1.9秒。
- **测试准备**：下拉性能采样先等待既有表格数据就绪标记，避免把初始化属性schema导致的tbody替换计入菜单操作；零重建断言保持。列偏好从已知查询前缀进入，再输入完整查询；导航从既有antimage查询进入。全量列表、空搜索、排序和连续滚动仍由独立旅程覆盖，原列／持久化／语言／导航断言保留。
- **并发与停止**：本机真实浏览最多2个worker，Linux每片仍1个。失败用例按原规则重试一次，仍失败则结束当前浏览任务并协同取消其他门禁，避免继续等待已不可能通过的整套流程。
- **只读查询**：首轮GitHub jobs查询收到属于images.apple.com的TLS证书，主机名校验失败，发布取消且main未更新。只读CI状态查询现在对传输错误最多额外重试2次，间隔1／2秒；TLS、候选SHA／基线校验不放宽，认证／权限错误、实际用例失败及写操作不套用该重试。

## 复现与交接

- `pnpm check --plan --base REF`核对范围，`pnpm check --base REF --lane core`执行核心；完整浏览需要全部`--lane browser --shard N/6`，单片不能代替完整CI。
- `pnpm check --retry-failed RECEIPT`仅作定向诊断，通过后仍需完整发布门禁。
- 经授权运行`pnpm push`，另一环境通过`pnpm sync`消费同一代码／数据基线；`pnpm push --status`和`pnpm data:status`核对结果。
- 本机证据位于`.medota2/sessions/ci-simplification-*`及发布／检查收据；这些忽略目录只属于本Mac，跨机器以本文CI链接和受管快照为入口。
