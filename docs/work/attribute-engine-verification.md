## 核验顺序

1. 只读盘点同版主 VPK、分卷及游戏二进制，记录路径参数、文件hash、工具版本、客户端版本。先用现有查看器提取与属性有关的脚本、定义、本地化和可读资源，输出清单及hash。不要用文件mtime推断游戏版本。
2. 查找公开资源中缺失的常量及参数调用关系：三属性换算、护甲曲线、攻击速度上下限与BAT、攻击／施法后摇、驱散强度与各效果可驱散性、转身速率、魔抗／闪避／状态抗性叠加、冷却与充能、吸血伤害排除。可读符号或API名称只能作线索，不能单独证明运行公式。
3. 在本地练习环境做可复现单变量实验。记录英雄、等级、技能、命石、物品、目标防御类型及所有被动效果；使用固定伤害输入并单独隔离护甲／格挡／魔抗。分别采样护甲0、7、负10；三属性增量；BAT不同英雄在有效攻速100／200及上下限附近的攻击时间。记录重复次数、时间步长与测量误差。
4. 攻击／施法后摇从同版模型动作资源和客户端接口取证，并做取消动作、连续攻击间隔、Shift队列、攻速变化与特殊技能对照。`IGNORE_BACKSWING`标记不能直接转换为0秒。驱散用普通／强驱散分别验证正负效果，记录技能含多个效果时的例外，不能把技能根字段推广到全部效果。
5. 用对照实验验证多个同类来源、免疫／驱散、英雄与非英雄目标，以及 VPK 巫毒面具文本排除的纯粹／反弹伤害。区分面板值、实际结算和本地化舍入。
6. 昼夜视野分别读取来源字段并在同版客户端核对；视野范围、地形遮挡、飞行视野、真视分别测量，不将“范围覆盖”当作实际可见。

## 产物与验收

每条结论提交来源文件／hash、具体token或符号、实验条件、输入／输出、截图或日志、置信程度和可复现步骤。必要原始资源留在获准的本机目录，交接可复核的摘录与摘要。结果相互矛盾时保留两边证据，不能只改页面数字使其一致。

Mac消费时按固定来源提交关联结果，更新属性证据、公式说明及针对性已知答案测试，并复验对应对象双向跳转；更新环境登记的实际能力与本任务状态。只有同版实验完成才可把“待引擎复核”升级为“同版实测”。
