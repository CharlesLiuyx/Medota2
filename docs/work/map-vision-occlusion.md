## 当前可用算法与后续接入

`src/domain/map/vision.ts` 提供 `createVisionSolver(scene, sources, options)` 与 `sampleVision`，算法版本 `approx-ground-vision/1`。纯 TypeScript，无 Node／DOM 依赖，可由后续 Web Worker 直接调用；`src/server/map/vision.ts` 只负责把选定文件包准备成可序列化场景，不读取数据库，也未接入服务端路由。

首版规则：

- 二维距离不超过来源半径；同队多个来源取可见并集，调用方分别传入各队来源。昼夜由调用方选择同版半径，不在算法内维护游戏时钟。
- 树木用半径64的圆，观察者到目标的线段碰圆即遮挡，包含相切；目标在树前不受影响。观察者位于候选圆内时忽略该树，避免近似尺寸把来源完全困住。`removedTreeIds`模拟砍树，重新建立求解器即可恢复。
- VHCG按64单位格中心取样；地面高度以 `floor((z + 64) / 128)` 分层。射线每半格采样，遇到比来源更高的层则遮挡。它是粗略高地模型，不是引擎FoW高度，也未实现坡道／边缘特殊规则。
- `treeRadius`和`heightBand`可调，64／128是模型选择，不是实机测量。树木暂不按Z筛选，所以悬崖旁的树可能过度遮挡。
- 输出 `visible`、`blocked`、`out-of-range`或`unknown`。阻挡附树木ID或地形原因，是一个解释线索，不承诺最近／唯一阻挡体。缺高度返回未知；可证明有树遮挡时仍可返回阻挡。一个来源未知、其他来源阻挡时整体仍未知；任一来源可见则整体可见。
- 输出网格按世界Y递增逐行保存，默认64单位采样，代码0／1／2／3对应范围外／可见／遮挡／未知。最大一百万采样点；交互性能预算留到页面接入时实测。

已有原生包的2475棵树与VHCG可直接复用，读取高度原字节前核对provenance哈希。场景记录地图哈希、客户端、原来源、Dataset revision、导入和准备时间、适配及schema版本；不修改原包或`coverage.vision=false`。旧版无高度时保留未知，不借用6944数据。

本轮不解析专用FoW线阻挡／肉山区域、不提供真实飞行视野、不处理实体隐身／真视／获得与失去视野延迟。原生节点已抽查到重复targetname和缺失TargetNode，不能按名称或文件顺序猜连线。这些限制随离线场景一起交付，不阻塞普通地面模拟的后续开发。

### 本机复现

使用现有依赖；Windows沿用环境登记中便携Node22的进程局部PATH。以下是离线命令，无需启动游戏、Web或数据库；输入可配置，输出父目录需存在、目标目录必须不存在且位于Dataset之外。

```sh
pnpm exec tsx src/workers/sample-map-vision.ts --input .medota2/maps/7.41f-6944-economy-v3 --output output/vision-example-new --x -3000 --y -2000 --radius 1800
```

生成`scene.json`（来源身份、限制与算法输入）、`samples.json`（可见性网格与编码）、`report.json`（参数、代码文件哈希、复现参数和计数）和`preview.svg`（可见／遮挡／未知及树木圆示意）。路径中的版本只是显式输入示例，不是代码默认路径。数据和图片在忽略目录，不是跨机器附件；可按命令重建，原始资源不进入代码Git。

少量回归覆盖树前后、相切、砍树、多来源、高低地、缺高度、半径边界、错误输入和来源哈希失配，见`tests/unit/map-vision.test.ts`与`tests/unit/map-vision-source.test.ts`。真实样例和验收见[准备验收](../history/2026-10-08-map-vision-preparation.md)。运行成功及合理形状不代表游戏内精度验证。

后续页面工作只需：按所选Dataset准备场景 → 用同队来源和树状态建立求解器 → Worker采样并绘制覆盖层 → 选点查询原因。缓存键包含Dataset revision、算法／参数、来源与树状态；变更后取消旧任务。页面入口、控件、Worker生命周期和中英界面均尚未实施，待用户另行启动。

## 可选精度升级的目标与完成条件

在 Medota2 地图上，根据指定版本的地图、视野来源、昼夜与树木状态，计算并展示视野遮挡；解释某个目标为什么可见或不可见。最终以同版本引擎输出验证准确性。

完成条件：

- 输入数据、算法与验证样本均有明确版本；参数缺失、来源不一致时显示不支持或待核验。
- 地面视野覆盖树木、地形高度、专用视野阻挡；飞行视野按对应补丁处理特殊区域；多个来源按队伍合并。
- 地点可见与实体可见分别验证，保留计算结果和界面渲染的区别。
- 独立测试集报告误判可见、误判不可见、边界误差和时间差；通过的版本、条件与未覆盖场景明确列出。
- 地图 Spec、检查映射和图谱随实际实施更新。有限样本一致只能声明“在该版本、该测试范围内一致”，不能声明已证明所有状态等价。

圆形模型的完整遮挡角为 `θ = 2 asin(r/d)`，其中 `r` 是有效视野遮挡半径，`d` 是观察者到圆心的距离，条件为 `d > r`。目标还需位于遮挡体后方：用观察者到目标的线段与圆相交判断，不能只检查角区间。这个数学结论不等于已取得 Valve 的完整实现。

## 阶段一：确定版本与输入合同

依赖：无。环境：Mac可完成资料与合同设计；当前不需要数据库变更。

- [ ] **V1 固定目标版本**：优先核对现有7.41f／6944地图与可用客户端是否匹配；读取实际客户端、服务器、地图哈希及工具身份。若无法获得同版引擎，保留该版本待验，另建新版本实验，禁止混合6952转储与6944地图声称验证完成。
- [ ] **V2 盘点输入缺项**：核对树身份／坐标／状态、FoW高度、线阻挡节点引用、区域形状、视野来源半径／类型／队伍。区分GNV导航格、VHCG地面高度与FoW计算输入，不把同为64单位视为语义相同。
- [ ] **V3 定义计算合同**：记录Map Dataset ID与revision、客户端／地图版本、算法／schema版本、参数证据、观察者XYZ、视野半径／类型、队伍、昼夜及树状态摘要；输出可见性网格、可选边界、遮挡原因及验证状态。地点查询与实体查询分别定义；缺未知数据时显式返回不支持。
- [ ] **V4 确定复用接口**：审阅现有地图Worker、取消／进度／结果失效逻辑及服务端数据加载，确定最小新增模块；新增来源适配独立实现。若涉及新框架、服务、迁移或环境，按项目规则补充设计与范围。

验收：输入清单、来源对应表和拟议合同可审阅；每个缺项有获取路径。此阶段不把候选规则写成现行地图行为。

## 阶段二：建立引擎参照样本

依赖：V1、V2。推荐环境：[已登记Windows客户端环境](../development-environments.md#windows-客户端与平台验证)，需重新核验版本和Workshop Tools能力。环境推荐不等于远程执行授权；与[属性机制核验](attribute-engine-verification.md)中的视野实验复用同版准备。

- [ ] **E1 制作采样脚本**：用临时FoW viewer和位置查询记录每个采样点；用实体接口另记目标可见性。日志包含输入身份、坐标、采样时间、实际返回值；实验结束清理自己创建的viewer。
- [ ] **E2 隔离与空地校准**：测试队伍排除其他英雄、建筑、守卫和技能来源；先验证无viewer的全暗对照。改变R及观察者格内偏移，用1／8／32／64单位步长扫描，确定取整、范围边缘和稳定所需时间。
- [ ] **E3 单树与遮挡体校准**：覆盖多距离、多方位、格内偏移、相切、贴树、观察者落在候选遮挡体内、原生树与临时树；用 `r候选=d sin(θ测/2)` 检验单圆假设，并比较方形／其他候选形状。相同输入重复采样以区分抖动与规则差异。
- [ ] **E4 高度与区域校准**：覆盖同层、高低地互视、坡道、树高度、线阻挡两侧、肉山坑内外及飞行视野。保留树木砍伐／恢复前后和多个来源的对照。
- [ ] **E5 地点／实体／时间校准**：比较点采样和实体接口、目标体积／原点、获得／失去视野延迟；排除隐身、显形等额外状态，再独立验证这些状态的接口边界。界面雾边截图只作辅助证据。
- [ ] **E6 固定回归样本**：划分拟合样本与独立验收样本；保存输入、输出、步长、重复次数、版本和哈希。原始游戏资产仍按许可与数据协议保存，只交接必要样本和证据摘录。

验收：有可重放的同版参照集，明确采样分辨率与仍未识别规则。不能因实验条件缺失，将社区参数标为引擎常量。

## 阶段三：实现与校准算法

依赖：输入合同；几何基础可与阶段二独立开展，Dota规则定型依赖E2–E6。

- [ ] **A1 实现可解释的几何基准**：在 `src/domain/map/` 规划独立视野模块。先覆盖圆的线段相交与角区间、线段／多边形遮挡、跨±180°的区间合并；明确相切、零长度及观察者位于遮挡体内的策略。策略在实机证据确定前标为候选。
- [ ] **A2 建立网格参考求解器**：采用易核对的逐采样点几何判定作为基准，绑定经确认的网格原点、取整、采样规则和高度筛选；输出二值可见性及诊断原因。几何正确性与游戏一致性分别检查。
- [ ] **A3 实现高效求解器**：评估空间索引、环扫描与阴影区间合并；先和参考实现比对，再和引擎参照比较。明确复杂度、提前终止条件及近远遮挡处理；不因性能优化跳过特殊规则。
- [ ] **A4 接入版本规则与状态**：树木／地形／区域阻挡分别适配；组合昼夜半径、地面／飞行模式、队伍来源并集、动态树状态。对未支持技能／实体状态保留明确边界。
- [ ] **A5 差异定位与精度报告**：对独立样本逐点比较，分别统计误判可见、误判不可见、边界位置误差与时间差；将差异定位到数据、几何、网格、高度、版本或实体规则。未消除差异前保留“估算／待核验”标识。

已知答案最小集：圆形模型 `r=64`，`d=128/256/512` 对应 `60°/28.95502437°/14.36151156°`；包含树前目标、树后目标、偏离阴影、相切、零长度、角度跨界和重叠遮挡。方格与其外接圆应得到不同的张角，防止把近似当等价。补丁特例必须有独立样本。

验收：几何基准正确，优化实现未改变既定语义；独立引擎样本的差异和适用范围可审阅。未完成实机核验的版本不能升级为“已验证”。

## 阶段四：接入地图与计算生命周期

依赖：A2–A5形成可声明精度的结果；显示模型与数据合同先同步地图Spec。

- [ ] **P1 接入计算任务**：复用Worker，支持取消、进度、错误和任务身份；版本、参数或树状态变化后使旧结果失效，迟到的旧任务不得覆盖新结果。缓存键覆盖全部影响可见性的输入。
- [ ] **P2 接入视野交互**：可选择或放置视野来源，设置半径／昼夜／视野类型并查看遮挡结果；提供选点可见性、遮挡原因和当前精度说明。半径参考圈与遮挡结果分别表达，具体控件布局沿用最新地图工作台。
- [ ] **P3 验证状态变化**：版本切换、移动来源、砍树／恢复情景和多个来源变化都重新计算；缺地形或FoW输入的版本显示明确原因，不借用其他版本数据。
- [ ] **P4 处理渲染与性能**：渲染平滑不改变二值判定；只重算相关来源／区域。用同版本固定场景测量多来源、连续移动、缩放与取消，先记录基线并制定交互预算，再优化并复测。

验收：少量有效旅程覆盖“选择版本→设置来源→查看树后目标→改变树状态→切换版本”；验证旧结果隔离、中英界面、窄屏和性能。页面可见不等于引擎语义验收。
