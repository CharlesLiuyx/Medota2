# Tab响应与版本资源缓存

2026-10-11：批准的阶段0–3已实施，机器检查通过；响应目标部分达标，待页面人工审阅。完整范围、环境、1320次重复切换统计和验证证据见[本轮验收](../history/2026-10-11-tab-cache-performance.md)。

## 当前结果

- 生产导航420次热切换，点击反馈最大47.8ms；生产表格240次中有1次在4倍CPU下达到227.8ms，其余低于120ms。各页面反馈P95均低于55ms。
- 生产常速表格真实数据行出现P95为52.6／60.7／75.1／114.7ms；完整就绪为67.8／70.1／89.2／144.8ms，顺序为英雄／技能／单位／物品。120次表格热切换API请求为0。
- 4倍CPU下内容就绪仍明显超标，开发模式也有反馈和内容超标；首访、路由预取、持续快速切换、普通停留节奏分别记录，不能泛化为所有场景均低于120ms。

## 2026-10-13 首屏预热补充

网站水合与load完成后，空闲预取全部顶栏路由及四类图鉴首屏图片；按版本和响应式尺寸复用解码结果。后续移除单位独立loading占位，英雄／技能直接恢复已验证内存目录，英雄／单位首次渲染按视口选取分块，旧块复用且屏幕外本地追加可让出导航优先级。

最终正式构建54次切换均无首帧缺图；英雄／单位首帧覆盖完整第一屏，搜索和浮层可立即使用。桌面单位22–30ms，返回英雄25–123ms；普通停留的六来源返回英雄38–67ms。当前开发工作台单位首次182ms／返回66ms，返回英雄64–144ms，仍有路由请求开销。测量已区分录制开销、首屏完整性与常规停留，不能将前轮带trace的273–329ms直接作同条件基准。见[本轮切换验收](../history/2026-10-13-tab-switch-latency.md)；图片队列原始实现见[首屏预热验收](../history/2026-10-13-tab-viewport-preload.md)。
