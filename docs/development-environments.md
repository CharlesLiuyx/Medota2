# 开发环境与能力登记册

更新：2026-10-06。状态：已建立文档登记与任务推荐规则；自动环境探测、任务调度和跨环境数据同步尚未实现。

本文件集中记录各环境的职责、可用资源、适用任务、限制和验证依据。开始任务先查这里；当前环境缺少关键能力时，推荐已登记的合适环境，并给出可执行的交接说明。新增本地机器或云端环境也更新同一份登记册。

环境资源和工具可以不同。选择同一开发版本时，需要保持一致的是代码与可消费的业务数据；拥有全部上游仓库、完整游戏安装或全部提取工具不是每个环境的要求。版本交接方式见[多环境数据同步方案](specs/development-data-sync.md)。

## 登记与核验规则

- `environment_id` 是长期使用的环境标签，用于查找能力和交接。它不同于每次重建时生成的 `workspace_id`、数据库身份或远程连接工具的 host ID，不能直接当作连接地址。
- 能力按资源逐项标为“本轮核验”“既有核验记录”“用户说明”“待核验”或“计划”。注明日期、依据与范围；不能用整台机器的一个“可用”标识替代逐项检查。
- 登记中的路径只帮助在对应机器定位资源，不成为代码默认值。实际命令仍通过已有配置项／参数指定输入，不把其他机器的绝对路径复制过来。
- 本文件只保存非秘密信息。连接凭据、SSH 地址／密钥、数据库 URL、私有访问令牌和实时进程状态留在环境自身配置中。
- 仓库 HEAD 和安装版本是一次观察结果，不代表最新上游，也不自动等于产品正在使用的版本。运行前核对任务需要的精确 commit、构建号、文件哈希与工具能力。
- 环境下线、路径变化、工具失效或新增能力后更新对应条目。稳定事实在这里维护；`docs/current.md` 只记录任务进展并链接本文件，避免多份机器清单漂移。

- 资源证据：2026-10-06 既有项目核验记录确认存在 `game/dota/pak01_dir.vpk`、`game/dota/maps/dota.vpk`、`game/dota/steam.inf`，以及 673 个 `pak01_*.vpk` 文件。本轮用户再次说明此环境具有 Dota 2 客户端数据；本轮没有访问该机器重新探测。原始记录可在提交 `e5c8668` 的 `docs/current.md`「Windows 本地游戏资源来源」节复核。
- 版本证据：既有记录中 `steam.inf` 声明 `ClientVersion=6944`、`SourceRevision=11085649`，日期为 2026-10-05。这是安装声明，尚未完成 VPK 内容与来源 Git commit 核验；更新游戏后可能改变。
- 工具条件：当时 PATH 中未找到 Source 2 Viewer CLI；不能据此认定机器上完全没有安装。实际提取前需定位工具、核对可运行版本；安装、资源传输和发布仍按具体授权执行。
- 开发条件：Medota2 当前代码提交、Node／pnpm、WSL2、Docker、数据库状态与可用磁盘没有在本轮确认。需要在此运行应用或恢复数据时另行预检，不从“有客户端”推断完整开发栈已就绪。

建议将需要原始 VPK、原生地图、模型／材质／纹理／声音、客户端文件核对的步骤优先安排到此环境。若任务是游戏运行中的视觉或行为验证，可推荐到此核验运行条件，但资源存在本身不证明游戏可以启动或某项行为已验证。

**版本限制：**当前项目记录的图鉴为构建号 6918，既有 Windows 安装声明为 6944。需要复现 6918 时，先查找可核验的匹配资源；不能把 6944 提取结果标为 6918。若决定研究 6944，创建独立来源和数据版本，保留准确溯源。提取产物放到游戏目录外，原始安装只读；当前没有新增提取或导入。

## 遇到限制时怎样推荐与交接

1. 读取登记册，列出该步骤真正需要的资源、工具、系统及数据版本。
2. 在当前环境做范围明确的只读核对，区分代码问题、资源缺失、工具未就绪、权限限制和版本不匹配；完成仍可独立推进的工作。
3. 将缺项与登记能力匹配，推荐具体环境、需要转移的步骤及依据；标明证据日期、待核验条件和预期输出。
4. 给出交接内容：任务目标、代码提交／未提交补丁、数据基线、输入版本与路径参数、已做工作、复现／运行命令、输出文件与哈希／provenance、验收方式和回传位置。只写实际可用命令；拟议的同步接口不能当作当前命令执行。
5. 目标环境重新核验能力和版本；完成后回写登记中的新事实、任务记录及结果，再在需要消费产物的环境验收。登记与推荐不自动授权远程执行、向其他聊天发送任务、安装工具或上传数据。

## 新环境登记模板

在本文件中新增条目，未知字段明确写“待核验”，不从操作系统推断工具或资源存在。

| 字段               | 应记录的内容                                                  |
| ------------------ | ------------------------------------------------------------- |
| 环境标签与名称     | 稳定 `environment_id`、用户能识别的名称；不是访问凭据         |
| 类型与生命周期     | 本地／云端、OS／架构、长期／临时、重建或回收条件              |
| 主要职责           | 元数据、客户端资源、应用开发、平台验收或计算等建议用途        |
| 资源与定位         | 来源名称、环境内路径提示／配置键、commit／build、可用文件范围 |
| 工具与运行能力     | Node、pnpm、Docker、数据库、提取器、浏览器、GPU 等实际核验项  |
| 限制与阻塞         | 缺工具、版本冲突、容量限制、连接待确认、数据许可等具体问题    |
| 推荐任务与替代环境 | 哪些步骤适合在此完成，缺项时可转向哪个已登记环境              |
| 证据与时间         | 用户说明／命令核验／项目历史记录，核验日期、版本和范围        |
| 交接与更新         | 输入要求、产物与验收方式；最近一次更新者／任务记录引用        |

运行时实时状态仍留在工作区状态报告中。未来如增加自动推荐器，它应读取此处维护的能力与核验信息，并在执行前重新检查；本轮只落地可被开发者和 AI Session 使用的文档流程。
