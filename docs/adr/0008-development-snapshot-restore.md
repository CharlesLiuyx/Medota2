# ADR 0008：开发快照、独立候选恢复与工作区切换

- 日期：2026-10-06。
- 状态：按用户确认的多环境同步方案实施。

## 决定

开发数据以不可变快照经独立私有 Git／LFS 仓库交接。公开代码仓库只保存精确数据 commit、manifest SHA-256 和 schema 摘要。业务表按列保存 PostgreSQL 的文本表示与稳定主键顺序；二进制按 SHA-256 去重；来源 Git commit 和地图文件均进入依赖清单。原始大数据和凭据不进入公开代码仓库。

导出使用 Web 角色的单个 `REPEATABLE READ READ ONLY` 事务。合同增加有生命周期的只读事务回调，仍不向调用方提供裸连接、事务控制或多语句查询；事务外使用回调查询会失败。

恢复只使用 Migration 角色新增的 `restore` 操作，并同时要求：development 或 local-review 用途、精确数据库确认、受管新候选目录／lease 与当前身份及端口相符、候选未成为活动环境、导入前全部业务表为空。新库由现有 provisioning 与迁移创建独立身份、角色、权限和 schema。数据库恢复保留 ID 和来源时间，不导入控制 schema、角色、密码、receipt 或 migration 执行历史。

表按受审依赖顺序导入。`import_runs` 的三个结果外键先置 null，相关记录导入后在同一事务补回；外键和约束始终启用。identity 列使用 `OVERRIDING SYSTEM VALUE` 并在恢复完成后校准序列。未知表、列、schema 或不完整依赖拒绝恢复。

候选经业务摘要、来源和图片核验后，工作台在排他锁下停止，由一个原子活动清单同时选择数据库状态根与来源／地图目录，再重启。持久切换日志保留前后清单，健康检查失败回滚；旧数据库保留。工作区名称、UUID、端口及实例回执仅保存在忽略目录，每份 checkout 独立。

Git 操作不隐式恢复数据库，也不自动推送。发布先验证数据远端 commit 与 LFS 内容可获取，再锁定代码引用。分支冲突或本地未保存数据阻止自动切换；发布和远端资源上传仍需具体授权。私有资源发布范围与许可须在实际上传前确认。

## 边界

平台目标为本地macOS/Linux、Windows原生PowerShell和具备受管Docker能力的云端同机栈；WSL2可选。原生命令、ACL、进程和路径适配已实现，支持合同见[同步Spec](../specs/development-data-sync.md#windows-原生支持要求)，实际平台验收及限制只由[环境登记](../development-environments.md)维护。非production数据库仍仅loopback；远程production、托管PostgreSQL与公网查看入口不因此获得支持。数据库查看仅在显式开发工作台开启，使用Web只读角色、表列白名单和同源／Host检查。

数据快照记录已完成的业务数据；运行中的导入必须结束后再导出，内部 staging 表不在快照范围，Web 导出角色不增加其读取权限。外部来源只读并按 commit 准备，不把当前 checkout 当作最新或与已入库数据自动匹配。

## 验证

本机已完成真实快照往返、摘要比较、独立身份确认、原库／活动库恢复拒绝、重复应用及页面浏览。自动用例覆盖缺文件、损坏哈希、schema 不符、未导出修改／删除和切换写入保护；数据库合同修改执行完整隔离用例。完整跨平台及崩溃恢复矩阵仍需逐项验收；实际记录由环境登记及其链接的任务／历史维护。
