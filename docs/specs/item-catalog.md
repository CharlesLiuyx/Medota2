# 物品图鉴

## 页面与交互

顶栏顺序为英雄、技能、单位、物品、属性、地图、变化。物品入口 `/items`，详情 `/items/[internal-name]`，激活态覆盖目录和详情。沿用全局Release与紧凑深色样式；搜索、分类、语言、详情及配方链接保留版本参数。

目录支持中文、英文、内部身份、拼音及首字母搜索、分类、清空和URL恢复。语言由全局顶栏统一选择。使用InfiniteList本地数组适配器，首批48条，按共享上7屏／下10屏规则加载和回收；身份包含Catalog、查询、分类和语言。没有IndexedDB离线副本。卡片显示原生图标、双语所选名称、分类和明确价格；悬停及键盘焦点展示效果和基础属性，点击可完整阅读。

详情显示价格、已解析效果、冷却／魔耗／施法距离与来源数值；全部数值保留字段身份与条件，标签链接到[独立属性](attribute-catalog.md)。官方`$`变量先展开，未知字段明确保留为专属参数；原文HTML转为普通文本，未知数值明确待补充。配方保留可选方案、重复组件、图纸价格、成品和反向合成关系。来源中的星号条件保留特殊条件提示，不推测引擎含义。缺失关联对象显示待补充，不生成不存在的链接。有效来源中未知物品返回404；来源不可用显示资料未接入。

分类是来源辅助浏览：装备与消耗品、中立物品、中立附魔、合成图纸、其他物品。依据ItemRecipe、ItemIsNeutralActiveDrop／ItemIsNeutralDrop、ItemIsNeutralPassiveDrop和ItemPurchasable字段；未提供购买标记的普通定义归装备与消耗品，不据此证明在商店出售。来源包含历史、活动和禁用定义；目录及详情明确说明不代表全部可购买／掉落。价格0与未知价格区分，不推算缺失价格。

物品悬浮卡沿用共用HoverTooltip按属性内容收紧的宽度（最大720px，无固定最小宽度，受视口两侧8px留白约束）。桌面保持两列，每列的名称与数值分别对齐，按最长内容确定宽度；640px及以下视口改为单列。每项优先单行，窄屏长内容自然换行；说明文字随卡宽换行。详情页保留两列属性布局，浮层规则见[语义UI](semantic-game-ui.md#hover-tooltip-面板布局)。

## 来源与版本

复用所选已发布Catalog元数据，从固定commit的Git对象读取 `scripts/npc/items.txt` 和同提交双语abilities本地化，先校验数据库记录的steam.inf checksum。读取根目录与单位来源一致；不读取工作树改动，不联网请求最新资料。

物品是独立领域实体及只读模型，定义暂未持久化独立Item Dataset，图片另有独立资产批次。`item-snapshot.ts`最多缓存两版，保留完整原始KV、未知字段、文件hash、source_repository、source_commit、source_path、client_version、imported_at、导入器及schema版本；imported_at表示只读模型构建时间。重复身份、异常定义和空定义直接报错，不能被伪装成空目录。

名称识别来源中的`:n`键；仍缺失的历史、图纸和辅助名称使用按source commit限定的审阅资源，并将资源ID／内容摘要记入provenance。当前每版76个原缺名身份已补齐，2个未启用定义显示用途名标记；同版效果与数值仍由原定义提供。来源优先、证据与非正式名称规则见[名称补充](semantic-game-ui.md#经过审阅的名称补充)。

### 参数名称补充

部分官方参数标签被注释，正常KV解析不会读取；另有内部字段只存在于定义或效果说明。物品适配器v4在官方标签与已有明确映射缺失时，读取 `src/data/item-parameters/supplement.v1.json` 的双语补充。资源严格绑定source commit、物品身份与字段，当前覆盖7.41e／6918及7.41f／6944每版876处缺名；新版本或未审阅物品不自动套用。物品详情、悬停和独立属性引用共用适配结果。

`reviewed-labels.tsv`维护逐字段审阅文案，`owner-overrides.tsv`维护同名异义差别；运行时只使用已保存的逐物品绑定，不按内部名拆词生成名称，不自动合并属性身份。名称依据区分同版效果说明、经核对的注释标签、字段释义。注释可能过时，例如影之灵龛注释写总治疗量而同版说明与数值表示每秒恢复；名称按现有定义和说明核对，不能直接启用全部注释。

确定为比例的补充参数显示百分号，确定的时间参数在标签注明秒／分钟；保留原始正负号、0值与数值，不将加成量当作总量。穿刺与重击伤害、定值与百分比减速、幻象额外伤害与总伤害分别命名。仅能依据字段释义的名称保留机制待核验说明，标签悬停及属性关联的“字段与条件依据”可见。补充资源保存来源提交、客户端版本、文件SHA-256、定义行号、可得文本token／行号、导入时间与内容摘要；名称补充不证明历史／禁用参数当前生效。

只读核对：`pnpm exec tsx scripts/analysis/build-item-parameter-labels.ts <source-Git-repository> --check`。命令逐版核对资源摘要、源文件hash、定义和标签绑定，并验证物品参数缺名为0。省略 `--check` 按已审阅TSV重新生成资源；修改词表或新增版本前须逐物品审阅，生成后重新核对与浏览验证。

完整Release就绪检查要求同来源物品定义可读、图片覆盖完整物品身份集合；新增版本提升失败不会更改当前head。同步运行时文件清单包含items.txt，旧快照未携带该文件时页面明确缺失，后续经授权发布完整快照补齐。

机器Diff API尚未增加通用物品实体投影，既有7.41e→7.41f变化页的物品补充仍遵循[实体版本合同](entity-versions.md)。定义的独立持久化与通用跨版本Diff为后续扩展。

## 图片资产

列表、悬停、详情及合成组件都使用原生图片，保持88:64容器与原图比例。图片按所选Catalog读取独立 `item_asset_heads`，URL携带不可变图片批次 `v`；浏览器只请求本机数据库图片服务，离线运行不访问CDN。加载失败明确显示图片待补充。

导入器按物品内部名解析Valve Steam static物品图标；ItemRecipe图纸共用原生recipe图标并标记shared_icon，其余标记icon。任何图片缺失使整批失败，禁止生成替代图凑覆盖。保留URL、内容hash、来源、导入时间与转换版本，CDN的source_commit/client_version均为空，不声称与玩法构建一致。

迁移0011新增独立物品资产批次、绑定及按Catalog的head；复用asset_objects/blobs/variants。批次保留全部源身份，提升时校验身份集合、四级LoD与覆盖退化；worker只能追加，head由受审函数修改，重复导入相同内容复用同一批次。同步快照包含三张新表与head。

## 验证

`pnpm check`纳入物品浏览流程；专项 `pnpm test:journeys --grep items` 验证顶栏顺序、搜索／清空／分类恢复、列表／悬停／详情图片实际加载、历史版本图片批次隔离、手机无横向溢出、详情与配方、版本参数和404。合成单元用例核对已知价格、数值覆盖、配方重复组件、中立分类、异常身份及固定Git来源冲突；真实浏览核对当前版本。
