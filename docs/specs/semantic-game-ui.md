# 语义化游戏图鉴

2026-10-06 已实现。适用于全部英雄与技能的展示入口；物品复用语义文本、版本导航及紧凑控件，行为见[物品Spec](item-catalog.md)。

## 玩家页面

- 英雄目录按四种主属性排列，搜索和筛选保持 URL 可恢复。按用户要求改为高密度头像网格：桌面 12–15 列、390px 手机 4 列、间距 4px；格内仅常显肖像与姓名，近远程、定位和三项基础属性放入悬停提示与详情页，分组使用单行标题。跨分页批次连续排布，同一属性内不因加载边界留下空格；保留虚拟化的分块测量。自定义悬停卡立即显示头像、难度、属性、定位等级与移动速度，可移入浮层阅读，支持焦点、Escape 与边缘避让。
- 视觉规则：不使用装饰性边框、分隔线或背景网格；以间距、底色、字重与属性文字颜色组织信息。焦点／输入选中态不使用外框，统一以 2.5% 不透明度的浅色背景提示；所有单选下拉统一复用 `CompactSelect`，包括比较页与数据库字段筛选；支持受控 value 和普通表单 defaultValue，提交使用具名隐藏字段。下拉箭头统一为14px SVG并继承控件文字颜色，文本与图标按控件中心对齐。全部筛选菜单共用深色浮层、11px 字号与极淡选中背景，选项用勾标识；单选支持方向键、首字母定位、Enter 与 Escape，角色等级条属于数据编码。
- 首页标题为「英雄图鉴」，20px 字号；顶栏 28px，保留 Medota2 并接入生成图标。筛选和版本使用无外框紧凑布局，筛选浮层支持点击外部／Escape 收起。图标来源与提示词见 [生成记录](../assets/medota2-icon.md)。
- 英雄详情采用紧凑布局：英雄名桌面 20px／手机 18px，头像 56px／48px，主卡片三项属性横向排列；正文保持完整可读。技能区按手机／中屏／宽屏排列一／二／三列，技能数值、天赋、命石和属性面板收紧间距。详情导航固定在 28px 顶栏下方，锚点预留 77px 滚动偏移，避免遮住内容标题。滚动时自动高亮当前章节 Tab，按根级 scroll-padding 与章节 scroll-margin 的总偏移判定，流式章节到齐后重新读取位置；点击目标仍可见时保留高亮，手动滚动继续同步；宽屏并列的天赋／命石保留刚选择的章节。
- 英雄详情包含完整技能说明、技能图标导航、10／15／20／25 级天赋树、命石、基础属性与故事。历史命石明确标注“已移除”；隐藏空技能槽不展示。属性仍是来源基础值，界面明确说明尚未叠加属性、装备、天赋与命石。
- 技能目录与英雄目录共用 20px 标题、紧凑无框筛选及即时悬停交互。技能条目高 62px、图标 36px，手机两列、宽屏六至八列，跨批次连续排布；常显名称、技能类型、所属英雄。说明、冷却、魔耗和升级标识放入悬停卡，详情继续展示完整数值。目录 API 新增可选 `description` 字段，来自固定 Catalog 的本地化说明并通过已有数值语义层解析；不在悬停时另取当前版本。
- 技能目录与详情使用本地化名称、施法方式、目标、伤害、免疫、驱散、各级数值、冷却、魔耗、升级与机制说明。技能详情与英雄技能卡共用 `AbilityTooltip`。
- 产品可见文本不输出内部名称、数据库 ID、原始 JSON、来源哈希或引擎枚举。异常、无结果、未找到、环境提示和筛选选项使用可读中文。英文模式切换名称与游戏说明，界面操作标签保持中文。
- 目录继续使用已有无限滚动；单个英雄技能、八格天赋树和单个技能的有限语义字段直接展开，避免在原始数据表里查找。

英雄、技能、单位、物品和变化目录沿用属性页的标题布局：宽屏标题在左，搜索、数量、筛选和清除操作整组位于标题行右侧；搜索约240px，数量不被压缩。有限宽度和390px屏幕自然换行，保持输入、菜单与全部结果可用。移除页头重复的游戏版本／客户端信息，由统一顶栏选择版本；变化页移除重复的版本箭头摘要，起始版本菜单和全局所选版本保留比较上下文。英雄更新时间与技能滚动提示不占额外统计行；错误和重试继续可见。

变化页面使用紧凑分类表格，实体名称与图标共用`EntityReference`简述卡；来源与判断依据通过图标／数值提示查看。文本内引用由`EntityText`自动使用`EntityReference inline`：图标高为当前字号1em且不超过当前行高，英雄头像可适当放大至min(1.25em,1lh)；紧贴文字基线，英雄／物品保留横向比例，缺图SVG同样缩放。变化表格的对象和改动项列也使用inline图标，简述卡标题使用标准图标。表格行合并、连续虚拟滚动与方向／幅度估算边界见[实体版本](entity-versions.md#紧凑表格实体与影响排序)。

各顶栏Tab的用途、收录范围等补充描述统一放入标题旁的信息图标HoverTooltip，沿用属性目录的悬停、焦点、点击与Escape交互。单位／物品的历史、活动对象范围说明完整保留；变化页的数值排列说明同样收进提示。英雄／技能无额外页头说明时不新增文案；地图继续使用已有来源和帮助提示。来源缺失、错误与核验状态仍在页面可见。

方向与幅度同行，来源按钮不设额外最小高度；典型数值行约27px，长内容自然换行。

## 共用表格与合并单元格

全部Table入口使用`ui/data-table.tsx`的`DataTable`，横纵合并通过`TableCell colSpan/rowSpan`渲染（支持跨至组末尾的rowSpan=0）。当一个对象对应多条属性时，合并单元格中的内容默认组内吸顶：页面滚动避让全局顶栏，局部滚动避让容器顶端及已有吸顶表头；内容始终限制在所属单元格上下边界，下一对象进入时自然交接。横向滚动仍沿原列移动，保留原链接、焦点、HoverTooltip和可访问表格语义。

横向overflow容器会阻断CSS sticky相对页面滚动。基础表格在吸顶区间将原内容固定到视口，保留等高占位；组末使用固定的边界位移随表格移出，横向位置与裁剪跟随容器。仅布局／内容变化时测量合并单元格，缓存相对表格的尺寸与坐标；滚动帧只读取表格、表头和容器边界，批量更新必要样式，不逐单元格读取布局，也不更新React状态。ResizeObserver增量观察尺寸，MutationObserver处理虚拟块挂载／回收及筛选重建；只在存在合并单元格或吸顶表头时监听滚动，卸载清理观察器、事件与定位样式。上方避让距离复用根元素scroll-padding-top。GroupedTable表头通过TableHeaderCell固定原内容、保留原列宽与等高占位，限定在表格底部以内；页面与局部滚动都生效，合并单元格内容继续避让表头。

`ui/grouped-table.tsx`的`GroupedTable<Row, Group>`负责通用“多个Item、各有多条属性”布局：

- groups为`{key, rows, ...对象信息}[]`；空组省略，rowKey提供属性稳定身份。
- columns定义header、width、render；width支持CSS clamp以视口分配列宽；widthSample可提供当前完整筛选数据的无交互轻量样本，GroupedTable离屏测量表头和内容、加16px内距并写入列宽CSS变量，maxContentWidth同时限制样本内容宽度；样本使用实际字体和图标几何尺寸，字体／样本变化重测，滚动及虚拟块增减不触发测量；fitContent列让短内容按自然宽度完整单行，maxContentWidth约束长说明的最大宽度（默认320px，同时受实际列宽约束，超过后自然换行）。保持fixed布局，避免虚拟块挂载／回收时原生自动列宽跳动；详情列吸收剩余宽度。空间不足时只在表格容器横向滚动，不截断文本。`merged: true`列以整组纵向合并为优先，可有多个合并列。`mergeKey`表达完整内容身份（含实体链接、悬浮说明和来源），相同键的相邻格自动横纵合并为原生矩形colSpan/rowSpan；非矩形区域分成不重叠矩形，不丢失值或重排。cellProps／rowProps承接语言和页面标记；groupProps落在原组首行，所有行用data-table-group保留所属对象，避免与虚拟块混淆。
- identity绑定版本、语言、筛选及排序；组件只呈现传入顺序，业务计算、搜索和数据读取由调用方负责。
- 默认每组一个tbody及虚拟块；相同内容跨对象相邻时，先计算全表合并范围，再把跨越的对象共同纳入一个虚拟块。采用共享useInfiniteList的上7屏／下10屏预取及等高回收，完整对象和合并矩形都不会被回收边界切断。连续相同值可能扩大单块，这是完整合并的边界约束。未变化块复用渲染结果，tbody的ref保持稳定，避免每次加载重新注册全表观察器。横向宽表由组件容器承接。

例如库存、道具或任意对象均可提供`groups = items.map(item => ({key: item.id, item, rows: item.properties}))`，再定义“对象（merged）／属性／数值”三列；无需复刻变化页的Dota实体、来源或影响算法。变化页已经只提供上述业务列与行内容。技能数值、地图经济、开发工作台和数据库浏览的普通表格也统一使用DataTable；新增合并列必须使用TableCell，不能另写一套吸顶实现。

## 实时多语搜索

英雄和技能列表不再设置“应用筛选”按钮。搜索框禁用浏览器自动补全、自动纠正、自动大写和拼写检查，避免缩写输入被系统建议干扰。文本输入保留光标、原始大小写和空格，查询端统一规范化；选择筛选项即时生效。中文输入法组词期间不发起查询，确认选字后更新。在线回退路径把连续输入合并为一次请求（80ms窗口）；快照就绪后本机搜索不发送列表请求。清空与选择项不设等待窗口。

- 中文、英文、中文全拼、拼音首字母、常见别称可同时检索，匹配与页面显示语言独立。支持 NFKC、大小写、空格／连字符和拼音音调归一化；`ü` 与 `v` 等价。
- 多语索引在服务端按不可变 Catalog 建立，最多保留 8 个实体／版本索引；并发首查共享构建，失败不永久缓存。拼音词库只在服务端使用，重复的英雄归属词汇只转写一次。补充技能名仍须经过同版本 SHA-256 校验；来源文件首次缺失时使用库内名称，补充文件到位后重启服务重建索引。
- 别称在 `src/domain/search/aliases.ts` 中单独维护，不写入 Valve 源数据。短英文缩写和拼音首字母优先完整匹配，避免 `AM` 命中其他英文单词的中间片段；歧义简称返回多个对应对象。
- 技能支持“所属英雄 + 技能”组合，例如 `am blink`、`敌法 闪烁`；单独名称优先匹配技能，没有直接命中时再查所属英雄。名称搜索与状态、归属、升级等筛选叠加；默认 `current` 不扩大到模板／历史技能。
- 目录优先使用按版本保存在 IndexedDB 的完整快照，搜索、筛选、排序与后续分块在本机完成；当前语言另一目录提前加载。缺少快照时后台同步，仅传缺少的内容哈希块。在线回退路径保留最近32个查询、取消旧请求与递增代次保护。详见[浏览器缓存协议](browser-catalog-cache.md)。
- 地址栏通过原生 History API 更新，不为每个按键新增浏览历史；进入详情再返回、刷新和复制链接均可恢复。详情返回时也核对实际 URL，避免框架恢复旧的服务器初始值。
- 列表组件使用 memo 避免按键触发已呈现条目的重复渲染；结果沿用分块虚拟化和版本隔离；在线回退才请求cursor，数据库查询仍受身份合同保护。没有数据库迁移。

## Hover Tooltip 面板布局

所有HoverTooltip按内容自然宽度收紧：纯说明面板最大520px，包含属性列表的面板最大720px，不设固定最小宽度，并受视口减16px约束、两侧至少留8px。属性面板的说明段落随实际卡宽换行，不再由长说明撑到固定720px。面板内容可使用完整内宽，长说明自然换行，长面板在视口内纵向滚动。

属性列表在桌面保持两列，每列共享名称与数值的自然宽度轨道：名称和数值分别纵向对齐，名称和值的轨道间距8px，两列间24px，行间6px。以每列最长内容决定宽度，消除均分列及固定卡宽造成的多余空白。640px及以下视口改为单列。每项优先一行显示，超长名称／数值受面板宽度约束自然换行，不能截断值或造成横向溢出。规则作用于浮层内部的dl条目，详情页的多列布局由原组件负责。英雄的三围、定位等级等紧凑指标保持每项完整单行。实体简述、物品、单位、技能、来源和页头说明使用同一宽度边界。

卡内游戏属性使用EntityReference的行内图标、名称、属性简述和详情导航，AttributeLink复用同一实体呈现。身份来自对象类型／对象键／字段及官方标签token，经attributeId映射，不能按翻译后的名称猜测；保留所选Release和语言。变化实体的facts携带属性投影，版本值等非属性元信息保留普通文本。父卡内可继续悬停／聚焦属性卡；父卡保持挂载，指针可进入子卡，Escape一次关闭最深一层，外部点击关闭整条卡片链。

## 悬停与导航性能

- 悬停状态按卡片订阅，切换时只更新旧、新两个锚点；卡片使用 memo，分页追加时复用已有条目。浮层定位在首次显示时同步完成，滚动／缩放用 requestAnimationFrame 合并。
- 顶栏图鉴链接使用完整路由预取；英雄／技能卡片仅在当前悬停或聚焦持续 120ms 后启用完整预取，离开即关闭该锚点的预取资格。提示本身立即出现，不等待预取。快速划过列表不会预取所有详情。
- Next.js 客户端路由缓存的 dynamic／static 窗口统一为 300 秒，快速往返可复用完整页面。窗口内可能仍显示之前发布的版本；浏览器刷新或 router.refresh 立即重新读取当前指针，窗口过后导航也会重新读取。可见目录每60秒轻量检查版本，变更后先补齐快照再刷新页面；查询与分块始终固定同一 Catalog 与 asset 版本。
- Next.js 开发模式关闭自动预取；日常 `pnpm dev` 受益于组件、查询和已访问路由缓存优化，正式构建另有完整路由预取。首次开发编译、尚未预取或缓存过期的详情仍需加载，不承诺所有环境下零等待。
- 英雄玩家详情只批量读取展示需要的英雄、定位、本地化和命石，避免拉取来源文件清单和比较记录。React 请求缓存合并 metadata／正文与重复本地化读取，不跨请求缓存 current head。技能页面并行读取英雄选项与游戏版本。
- 游戏版本仅缓存已确认的不可变 Git 结果，键包含来源根目录、commit 和 steam.inf checksum，上限 16；每次仍先检查数据库记录，不缓存失败。可变本地化文件每个请求仍校验完整 checksum，解析结果沿用有界缓存。
- 不更改上方 7×／下方 10× 视口预加载、数据库身份验证和发布规则；无新增运行依赖或数据库迁移。

## 展示语义

`src/presentation/dota.ts` 是无副作用的共用转换层；版本变化展示由 `entity-changes.ts` 复用同版名称、天赋与单位规则，按[实体版本合同](entity-versions.md#玩家可读变化与官方说明)组合官方说明。优先使用同版本官方本地化标签，已知字段提供中文标签；物品与技能数值标签链接到[属性实体](attribute-catalog.md)；`$armor`等变量按同版官方词条展开。未知参数按对象隔离，保留字段与数值并明确语义待核验，不自动猜同义关系。

- `AbilityValues` 中的冷却、魔耗、距离、前摇、持续施法、伤害覆盖继承的顶层默认值。
- 同一技能各级数值以 `/` 分隔，数值保留真实顺序，清除无意义小数尾零。
- `%field%`、`{s:bonus_field}`、换行标签与百分号转成普通文本；React 转义输出，不执行来源 HTML。
- 天赋显示值来自同版本数值条目的同名天赋 modifier；不把天赋内部名展示给玩家。
- 神杖、魔晶说明使用对应条件生效后的数值。可确认的加减、乘法、替换被解释；复杂条件不作未经验证的计算。
- 没有名字或无法解析的值明确显示“名称待补充”／“数值待补充”，不将代码、空值或对象序列化成正文。未本地化但有可读英文名称时保留英文名称。

### 经过审阅的名称补充

名称读取识别Valve的`:n`后缀键，保留原始键；明确的无后缀键优先。`src/data/entity-names/supplement.v1.json`是独立、可审阅的名称资源，按实体类型／内部身份维护中英文名称、证据URL、固定commit、文件SHA、客户端版本和名称类型；内容摘要随只读模型provenance保留。完整来源文件仍在可选外部仓库，补充资源只提取所需名称及来源记录。

补充仅适用于资源声明的source commit，当前为7.41e／7.41f；不按分支、最新版本或相似内部名扩展。已校验的同版文本优先，缺名时使用同版其他文本、历史名称或定义中的明确关联；图纸依据成品名称派生。历史文字仅用于命名，不复制历史说明、数值、状态或技能行为，不改写不可变Catalog。

确无正式名称的辅助、模板、活动或未启用定义，采用逐项审阅的描述性名称，并在中文显示“（用途名）”、英文显示“(descriptive)”。这是用途说明，不宣称正式游戏名称。未审阅身份和未声明版本仍保留缺名提示；不得按内部名自动拆词凑名称。英雄／技能／命石通过游戏文本服务读取同一资源，单位／物品在固定Git只读模型构建时应用；列表、悬停、详情、关联链接和双语搜索共用结果。英文原名或原文语言标识继续遵循[全局国际化](global-i18n.md)。

名称补充进入浏览器目录内容与搜索词，协议3使协议2及更早的缓存重新获取；后台块摘要继续验证实际内容。新增来源或扩展适用commit须重新审阅并更新资源版本。2026-10-07的全量盘点与证据见[补充记录](../history/2026-10-07-name-enrichment.md)。

## 本地化文件与版本

应用自有游戏术语以官方 VPK 文案作为初始语料；消息键与 token 的审阅绑定、精确来源及词典优先级见[全局国际化](global-i18n.md#官方-vpk-初始语料)。该词库不覆盖下面按 Catalog 固定版本读取的实体正文与专用标签。

当前数据库已保存英雄／技能名称、描述、数值及来源 checksum；尚未单独存储所有数值标签、机制注释与命石文本。`getGameLocalization` 因而只读补充文本：

1. 查询选定 Catalog 的源文件 checksum。
2. 从 `DOTA_VPK_WORKTREE_ROOT/<source_commit>`（默认 `.medota2/cache/worktrees`）或 `DOTA_VPK_UPDATES_PATH` 读取同名本地化文件。
3. 对完整文件重新计算 SHA-256，匹配后才使用；解析结果按 checksum 有界缓存，token 查找不区分大小写。
4. 文件缺失、版本不符或解析失败时退回数据库已有文本与已知词汇；不请求网络、不导入、不切换当前数据、不写数据库。

这意味着不携带匹配来源文件的独立部署仍可展示已存技能效果和基础数值，但命石说明及专用数值标签可能不完整。下一次持久化模型升级可将这部分文本一并纳入不可变 Catalog；本次未迁移数据库或改变导入版本。

## 游戏性版本

页面区分「游戏版本」与客户端构建号。`getGameplayVersion` 从上述可配置 Git 来源执行 `git show <source_commit>:steam.inf` 和同 commit 的 `scripts/change_log.txt`；steam.inf 的完整 SHA-256 必须与 Catalog 记录匹配。按变更时间选择不晚于来源构建日期的最新合法 `patch_name`，不会读取未提交改动或把上游最新版本贴到旧数据上。当前真实数据映射为 7.41e／6918。

该功能需要可执行的 Git 和保留对应 commit 的可选来源仓库；缺失时明确显示「游戏版本待确认」，不影响其他图鉴数据。补丁名称后续也应随 Catalog 持久化；本次不增加在线请求或数据库迁移。

## 运行与验证

沿用 `pnpm dev` 与 `http://127.0.0.1:3000`。更新代码后执行 `pnpm install --frozen-lockfile` 安装锁定的服务端 `pinyin-pro`（MIT）；不需要额外服务。

- `pnpm check --plan` / `pnpm check` 选择受影响的检查。
- `pnpm test:journeys --fixture` 验证固定已知数值及 390px 布局。
- 悬停回归用 200 个锚点验证切换只更新两个组件，并验证短暂停留取消预取、Escape 和单浮层；既有浏览器流程验证 Tab、详情往返、搜索和分页。
- 搜索单测验证中英文、拼音、首字母、别称与无结果；E2E 验证实时选项、输入法、请求合并、缓存、过期响应、URL 返回及跨语言搜索。
- 语义单测覆盖继承值覆盖、天赋、神杖条件、占位符与未知枚举；浏览器验证正文无原始 ID、图片、导航、筛选、语言切换与手机无横向溢出。
- 完整审计和原始来源仍由既有 Catalog 查询、CLI 与数据库记录负责。

### 天赋卡片等级

技能目录天赋卡在常显类型行展示等级（例如「25 级天赋 · 昆卡」），悬停摘要同步展示。按同版本英雄当前天赋绑定顺序两项一层，依次为10、15、20、25级；同一天赋在不同英雄的等级去重列出。缺少当前绑定时标明等级待确认。等级元数据随目录快照保存；现行协议3同时包含名称补充，旧缓存重新获取。

### 影魔毁灭阴影合并卡

影魔英雄详情在三个技能定义均存在时，将毁灭阴影近／中／远距离整合为一张卡，技能快捷入口也合并为一个。三个距离切换按钮直接显示当前版本的距离数值，选中后使用该技能的完整说明、数值、升级信息和独立详情链接。切换在本地完成，不再请求后端；传入浏览器的本地化仅包含这三个技能的文本。原有三个技能锚点继续有效。技能目录、三个技能身份及数据库保持原样；定义不齐时保留各自卡片。
