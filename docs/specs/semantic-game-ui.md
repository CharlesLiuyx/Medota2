# 语义化游戏图鉴

2026-10-06 已实现。适用于全部英雄与技能的展示入口。

## 玩家页面

- 英雄目录按四种主属性排列，搜索和筛选保持 URL 可恢复。按用户要求改为高密度头像网格：桌面 12–15 列、390px 手机 4 列、间距 4px；格内仅常显肖像与姓名，近远程、定位和三项基础属性放入悬停提示与详情页，分组使用单行标题。跨分页批次连续排布，同一属性内不因加载边界留下空格；保留虚拟化的分块测量。自定义悬停卡立即显示头像、难度、属性、定位等级与移动速度，可移入浮层阅读，支持焦点、Escape 与边缘避让。
- 视觉规则：不使用装饰性边框、分隔线或背景网格；以间距、底色、字重与属性文字颜色组织信息。焦点／输入选中态不使用外框，统一以 2.5% 不透明度的浅色背景提示；全部筛选菜单共用深色浮层、11px 字号与极淡选中背景，选项用勾标识；单选支持方向键、首字母定位、Enter 与 Escape，角色等级条属于数据编码。
- 首页标题为「英雄图鉴」，20px 字号；顶栏 40px，保留 Medota2 并接入生成图标。筛选和版本使用无外框紧凑布局，筛选浮层支持点击外部／Escape 收起。图标来源与提示词见 [生成记录](../assets/medota2-icon.md)。
- 英雄详情采用紧凑布局：英雄名桌面 20px／手机 18px，头像 56px／48px，主卡片三项属性横向排列；正文保持完整可读。技能区按手机／中屏／宽屏排列一／二／三列，技能数值、天赋、命石和属性面板收紧间距。详情导航固定在 40px 顶栏下方，锚点预留 88px 滚动偏移，避免遮住内容标题。滚动时自动高亮当前章节 Tab，点击与手动滚动保持同步；宽屏并列的天赋／命石保留刚选择的章节。
- 英雄详情包含完整技能说明、技能图标导航、10／15／20／25 级天赋树、命石、基础属性与故事。历史命石明确标注“已移除”；隐藏空技能槽不展示。属性仍是来源基础值，界面明确说明尚未叠加属性、装备、天赋与命石。
- 技能目录与英雄目录共用 20px 标题、紧凑无框筛选及即时悬停交互。技能条目高 62px、图标 36px，手机两列、宽屏六至八列，跨批次连续排布；常显名称、技能类型、所属英雄。说明、冷却、魔耗和升级标识放入悬停卡，详情继续展示完整数值。目录 API 新增可选 `description` 字段，来自固定 Catalog 的本地化说明并通过已有数值语义层解析；不在悬停时另取当前版本。
- 技能目录与详情使用本地化名称、施法方式、目标、伤害、免疫、驱散、各级数值、冷却、魔耗、升级与机制说明。技能详情与英雄技能卡共用 `AbilityTooltip`。
- 产品可见文本不输出内部名称、数据库 ID、原始 JSON、来源哈希或引擎枚举。异常、无结果、未找到、环境提示和筛选选项使用可读中文。英文模式切换名称与游戏说明，界面操作标签保持中文。
- 目录继续使用已有无限滚动；单个英雄技能、八格天赋树和单个技能的有限语义字段直接展开，避免在原始数据表里查找。

## 实时多语搜索

英雄和技能列表不再设置“应用筛选”按钮。搜索框禁用浏览器自动补全、自动纠正、自动大写和拼写检查，避免缩写输入被系统建议干扰。文本输入保留光标、原始大小写和空格，查询端统一规范化；选择筛选项即时生效。中文输入法组词期间不发起查询，确认选字后更新。在线回退路径把连续输入合并为一次请求（80ms窗口）；快照就绪后本机搜索不发送列表请求。清空与选择项不设等待窗口。

- 中文、英文、中文全拼、拼音首字母、常见别称可同时检索，匹配与页面显示语言独立。支持 NFKC、大小写、空格／连字符和拼音音调归一化；`ü` 与 `v` 等价。
- 多语索引在服务端按不可变 Catalog 建立，最多保留 8 个实体／版本索引；并发首查共享构建，失败不永久缓存。拼音词库只在服务端使用，重复的英雄归属词汇只转写一次。补充技能名仍须经过同版本 SHA-256 校验；来源文件首次缺失时使用库内名称，补充文件到位后重启服务重建索引。
- 别称在 `src/domain/search/aliases.ts` 中单独维护，不写入 Valve 源数据。短英文缩写和拼音首字母优先完整匹配，避免 `AM` 命中其他英文单词的中间片段；歧义简称返回多个对应对象。
- 技能支持“所属英雄 + 技能”组合，例如 `am blink`、`敌法 闪烁`；单独名称优先匹配技能，没有直接命中时再查所属英雄。名称搜索与状态、归属、升级等筛选叠加；默认 `current` 不扩大到模板／历史技能。
- 目录优先使用按版本保存在 IndexedDB 的完整快照，搜索、筛选、排序与后续分块在本机完成；当前语言另一目录提前加载。缺少快照时后台同步，仅传缺少的内容哈希块。在线回退路径保留最近32个查询、取消旧请求与递增代次保护。详见[浏览器缓存协议](browser-catalog-cache.md)。
- 地址栏通过原生 History API 更新，不为每个按键新增浏览历史；进入详情再返回、刷新和复制链接均可恢复。详情返回时也核对实际 URL，避免框架恢复旧的服务器初始值。
- 列表组件使用 memo 避免按键触发已呈现条目的重复渲染；结果沿用分块虚拟化和版本隔离；在线回退才请求cursor，数据库查询仍受身份合同保护。没有数据库迁移。

## 悬停与导航性能

- 悬停状态按卡片订阅，切换时只更新旧、新两个锚点；卡片使用 memo，分页追加时复用已有条目。浮层定位在首次显示时同步完成，滚动／缩放用 requestAnimationFrame 合并。
- 顶栏图鉴链接使用完整路由预取；英雄／技能卡片仅在当前悬停或聚焦持续 120ms 后启用完整预取，离开即关闭该锚点的预取资格。提示本身立即出现，不等待预取。快速划过列表不会预取所有详情。
- Next.js 客户端路由缓存的 dynamic／static 窗口统一为 300 秒，快速往返可复用完整页面。窗口内可能仍显示之前发布的版本；浏览器刷新或 router.refresh 立即重新读取当前指针，窗口过后导航也会重新读取。可见目录每60秒轻量检查版本，变更后先补齐快照再刷新页面；查询与分块始终固定同一 Catalog 与 asset 版本。
- Next.js 开发模式关闭自动预取；日常 `pnpm dev` 受益于组件、查询和已访问路由缓存优化，正式构建另有完整路由预取。首次开发编译、尚未预取或缓存过期的详情仍需加载，不承诺所有环境下零等待。
- 英雄玩家详情只批量读取展示需要的英雄、定位、本地化和命石，避免拉取来源文件清单和比较记录。React 请求缓存合并 metadata／正文与重复本地化读取，不跨请求缓存 current head。技能页面并行读取英雄选项与游戏版本。
- 游戏版本仅缓存已确认的不可变 Git 结果，键包含来源根目录、commit 和 steam.inf checksum，上限 16；每次仍先检查数据库记录，不缓存失败。可变本地化文件每个请求仍校验完整 checksum，解析结果沿用有界缓存。
- 不更改上方 7×／下方 10× 视口预加载、数据库身份验证和发布规则；无新增运行依赖或数据库迁移。

## 展示语义

`src/presentation/dota.ts` 是无副作用的共用转换层。优先使用同版本官方本地化标签，已知字段提供中文标签；无明确语义的引擎字段不进入玩家数值列表。

- `AbilityValues` 中的冷却、魔耗、距离、前摇、持续施法、伤害覆盖继承的顶层默认值。
- 同一技能各级数值以 `/` 分隔，数值保留真实顺序，清除无意义小数尾零。
- `%field%`、`{s:bonus_field}`、换行标签与百分号转成普通文本；React 转义输出，不执行来源 HTML。
- 天赋显示值来自同版本数值条目的同名天赋 modifier；不把天赋内部名展示给玩家。
- 神杖、魔晶说明使用对应条件生效后的数值。可确认的加减、乘法、替换被解释；复杂条件不作未经验证的计算。
- 没有名字或无法解析的值明确显示“名称待补充”／“数值待补充”，不将代码、空值或对象序列化成正文。未本地化但有可读英文名称时保留英文名称。

## 本地化文件与版本

当前数据库已保存英雄／技能名称、描述、数值及来源 checksum；尚未单独存储所有数值标签、机制注释与命石文本。`getGameLocalization` 因而只读补充文本：

1. 查询选定 Catalog 的源文件 checksum。
2. 从 `DOTA_VPK_WORKTREE_ROOT/<source_commit>`（默认 `.medota2/cache/worktrees`）或 `DOTA_VPK_UPDATES_PATH` 读取同名本地化文件。
3. 对完整文件重新计算 SHA-256，匹配后才使用；解析结果按 checksum 有界缓存，token 查找不区分大小写。
4. 文件缺失、版本不符或解析失败时退回数据库已有文本与已知词汇；不请求网络、不导入、不切换当前数据、不写数据库。

这意味着不携带匹配来源文件的独立部署仍可展示已存技能效果和基础数值，但命石说明及专用数值标签可能不完整。下一次持久化模型升级可将这部分文本一并纳入不可变 Catalog；本次未迁移数据库或改变导入版本。

## 游戏性版本

页面区分「收录版本」与客户端构建号。`getGameplayVersion` 从上述可配置 Git 来源执行 `git show <source_commit>:steam.inf` 和同 commit 的 `scripts/change_log.txt`；steam.inf 的完整 SHA-256 必须与 Catalog 记录匹配。按变更时间选择不晚于来源构建日期的最新合法 `patch_name`，不会读取未提交改动或把上游最新版本贴到旧数据上。当前真实数据映射为 7.41e／6918。

该功能需要可执行的 Git 和保留对应 commit 的可选来源仓库；缺失时明确显示「收录版本待确认」，不影响其他图鉴数据。补丁名称后续也应随 Catalog 持久化；本次不增加在线请求或数据库迁移。

### 天赋卡片等级

技能目录天赋卡在常显类型行展示等级（例如「25 级天赋 · 昆卡」），悬停摘要同步展示。按同版本英雄当前天赋绑定顺序两项一层，依次为10、15、20、25级；同一天赋在不同英雄的等级去重列出。缺少当前绑定时标明等级待确认。等级元数据随目录快照保存，协议版本2使旧缓存重新获取。

### 影魔毁灭阴影合并卡

影魔英雄详情在三个技能定义均存在时，将毁灭阴影近／中／远距离整合为一张卡，技能快捷入口也合并为一个。三个距离切换按钮直接显示当前版本的距离数值，选中后使用该技能的完整说明、数值、升级信息和独立详情链接。切换在本地完成，不再请求后端；传入浏览器的本地化仅包含这三个技能的文本。原有三个技能锚点继续有效。技能目录、三个技能身份及数据库保持原样；定义不齐时保留各自卡片。
