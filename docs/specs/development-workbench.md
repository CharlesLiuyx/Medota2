## 使用体验

一个开发者可以同时使用多个 AI Session，共用当前工作目录、分支、开发服务和开发数据。本工作区默认地址为 `http://127.0.0.1:3000/heroes`（已初始化workspace以其origin为准），可以在同一站点内浏览其他页面。任何 Session 保存页面代码，Next.js 自动更新当前页面，尽量保留查看位置、URL 参数和组件状态。框架需要完全重新加载或组件重挂载时，临时组件状态可能重置。

启动时先顺序预热英雄／技能目录、各一条详情路由与浏览器快照接口，再报告共享服务就绪；仅执行只读请求。这样避免第一次点击遇到并发编译／整页热更新而丢失导航。预热失败记录到开发日志，页面仍可使用既有在线路径。

页面右下角的开发面板显示小样例状态、结果版本、移动速度示例、技能数量、耗时和内存。样例直接调用当前生产解析器，默认输入为 `tests/fixtures/vpk/`。首轮目标是预热后的界面约 1 秒、小样例约 2 秒，冷启动单独统计；不能把解析函数耗时当作保存到屏幕的全部延迟。

面板只在共享工作台的开发模式启用，页面可读取 development 或 local-review 数据，生产构建不显示它，开发 API 返回 404。控制操作限制在同源请求，只开放重算和取消。

## 页面数据与计算样例

`MEDOTA2_WORKBENCH_DATA=auto` 为默认值：已有 local-review 受管环境时，使用现有真实 Catalog 和资产；否则使用 development 数据库，空库才初始化 fixture。可显式选择 `local-review` 或 `development`，修改后重启工作台。所选环境保留原有数据库身份、权限和数据类别，不复制或清空已有数据。

真实预览先调用现有准备入口和资产审计，要求绑定完整、LoD 完整、零 generated fallback。失败明确报错，不静默退回测试样例。页面右下角标明当前数据来源。小样例在独立进程中计算，不影响页面所用的数据集。

浏览器关键流程同时检查头像实际解码和图片响应；真实预览额外要求来源为 exact/alias，禁止将 HTTP 200 的占位图当成头像验收通过。

## 即时反馈

- 开发编译保留Turbopack磁盘缓存，每次快照落盘后以`full`模式回收可释放的编译图；避免大内存机器长期保留全部中间状态。共享工作台默认给Next子进程4096 MiB JavaScript老生代预算，保留已有`NODE_OPTIONS`及显式堆配置；沿用Next超过堆上限80%时的请求后自动重启。该预算不等于整个进程的内存硬上限，原生编译内存、Buffer与瞬时峰值需单独测量。正式webpack构建启用内存优化，继续执行类型及构建门禁。
- Next开发服务器的React调试信息随请求返回，避免没有HMR连接的预热／HTTP探针留下待连接通道。Next16.3.3的React Flight异步祖先跟踪会累积长寿命任务的`previous`／`awaited`历史；仅开发阶段通过Node同步模块加载钩子停用此可选调试跟踪，保留普通async hooks、请求AsyncLocalStorage、当前错误栈和热更新。四种开发AppPage runtime均受版本与完整SHA256约束，不修改安装文件；生产阶段不安装。兼容身份不匹配必须复验上游修复后移除或重新审阅，不能无依据扩展匹配。Node支持范围与package engines一致，使用registerHooks要求22.15及以上22系列或24及以上版本。
- 页面、组件和样式由 Next.js Turbopack 的 Fast Refresh 更新；共享工作台、独立真实审阅与浏览测试使用相同开发编译器。正式发布构建继续使用既有 webpack 路径。
- Tailwind 只扫描 `src/`；文档、测试及业务数据锁的保存不触发全站样式重编译。新增位于 `src/` 外的界面模板时须显式登记样式来源。
- 开发面板在隐藏标签页暂停轮询，恢复可见时立即读取最新状态；同一面板最多一个请求在途，状态未变不重绘，结果版本变化仍刷新当前页面。
- 解析、领域规则、共享库或 fixture 的文件变化，会合并到一次小样例任务；短时间连续保存使用 180 ms 合并窗口。
- 查询服务变化也触发反馈，并刷新当前路由的数据。解析输入未变时复用计算结果。
- 每次执行使用新的子进程，当前并行上限为 1；旧任务及时取消，回传结果前后检查版本，只有当前任务可以更新显示。
- 启动时或输入未变时，按内容摘要复用样例结果。默认样例无外部网络及数据库写入。
- 错误显示在同页，下一次保存自动重试。计算期间保留上一结果并明确标记过期。
- 迁移及运行配置变化显示待准备原因，运行 `pnpm dev:restart` 后恢复。持久数据不会在日常重启中清空。

## 数据库读取与故障恢复

共享工作台无论读取development还是local-review，都只对每个物理Web/read连接首次完整审计；每次借用恢复会话基线、检查角色及只读事务，新连接重新验证。独立审阅入口、test／production和写入操作不复用审计。权限、迁移及连接实现变更后运行`pnpm dev:restart`。

连接池空闲断线不终止Web进程；读取中断废弃故障连接，后续请求重连。错误仅保留timeout／unreachable／capacity／unknown分类，不暴露数据库URL、驱动原文或凭据。变化页的预期连接失败显示页内重试入口并保留全局导航，重试保持URL条件；根布局版本索引读取失败退回未验证状态。身份不符、权限漂移、非法版本与程序错误仍按原合同处理。

## 按需验证与 CI

`scripts/development/check-plan.mjs` 是唯一范围规则，同时供本地和 CI 使用。它只使用 Node 内置能力，CI 可以在安装浏览器和准备数据库前规划。

规则按模块维护：文档检查格式、链接／锚点、命令与入口；地图文件／算法／组件选已有地图专项；地图UI和视野场景读取另选`map:`浏览旅程（真实地图版本、Worker、取消、语种及窄屏；来源类型、Esc选中／占格、反隐高亮与英雄图标搜索），无地图的fixture明确跳过该真实数据旅程，合成场景由单测覆盖；单位选单位专项及使用流程。Hero／Ability解析继续核对已知答案，持久化变化加入数据库检查；共享基础和未知影响范围保守扩大，数据库合同／迁移执行完整隔离合同，工具链扩大到单测与构建。纯文件地图不默认启动产品数据库，涉及Catalog读取的地图服务仍检查数据库依赖。英雄小地图图标清单／导入器／只读图片入口触发地图旅程和图片专项；未收窄的持久化依赖仍扩大验证。日常UI逻辑更改不构建完整Web；`src/**/*.css`新增、修改或删除须执行正式构建，覆盖开发Turbopack与生产webpack在CSS模块及样式打包上的差异。

局部任务默认使用范围卡的 `--files` 集合，混合修改按范围并集验证；组合交付才检查全部未提交改动或 `--base`。登记的无交互展示组件与静态翻译资源使用现有组件／资源测试：当前包括 DatasetBadge、en.json、zh-CN.json、official-terms.json；规划器自身使用范围边界测试。发布CLI的push入口及publication目录内已登记的候选、收据、工作流和CI模块使用发布故障专项；导出器、未知新增模块或专项缺失仍扩大检查。登记依据是职责与已有测试，不按“改动行数少”推断安全；组件新增交互／数据读取时移出该登记。登记源或对应测试缺失时退回保守规则，未知文件、删除、运行器及构建工具变更继续扩大。检查执行器、CI workflow／矩阵规划、本机调度、浏览分片或耗时表变化，覆盖完整旅程、英雄／缓存／视觉三个E2E文件的桌面与移动项目及完整数据库合同，验证调度边界。

已核对的英雄配装计算与展示、物品定义／导入／仓储、英雄装备与状态服务按模块登记现有单测与下游旅程。配装计算覆盖英雄、技能及浮层；物品覆盖物品、装备、状态、属性、名称、版本变化与地图视野跨模块流程；涉及导入／查询以及HERO_STATS_FIELDS仓储投影时继续运行数据库检查。混合改动取并集，未知路径、删除源文件或登记测试缺失退回保守范围。纯配装计算不触发无关解析基准或数据库检查。地图、单位与页面组件继续使用各自已有映射。登记边界变化须更新消费者与范围测试。

视觉合同独立于真实数据旅程：英雄目录、技能详情及共同布局／导航／品牌图片变化，按登记的页面依赖选择`tests/e2e/visual.spec.ts`，显式核对桌面与移动项目。`public/brand`进入运行范围，公共资产参与输入摘要；地图、单位等无关局部变更继续走各自专项。直接改动E2E时同样覆盖两个项目；快照变更映射到所属spec，与独立视觉任务去重。视觉差异先核对旧图、实际图和合同，再更新各平台基线；不放宽阈值、不把一个平台的图片冒充另一平台已验证。Linux基线额外区分arm64与x64：前者来自已登记的本机容器，后者来自Ubuntu24.04 GitHub Actions；跨架构字体环境不共用图片，Mac既有路径保持有效。新增视觉依赖同步规划器与边界测试。CI保留真实旅程及fixture两种报告目录。

图鉴共用列菜单变更同时选择四类图鉴旅程和共用表格单元；几何交互等待完整对象、列目录与所选列值就绪，再以普通指针验证整列表头留白处的菜单，不使用force点击。浏览流程以明确的标题前缀区分地图、目录、悬停、版本导航、变化页、语言及名称，避免 `heroes` 子串把所有流程一起选中。语言资源只验证消息覆盖、词汇与插值，语言解析／Provider／proxy改变仍验证语言切换与跨页面流程。只改既有或新增journey文件时执行这些完整文件，不按标题过滤；删除文件、公共测试依赖变化或混合产品范围继续保守扩大，确保未登记标题也被执行。

浏览器测试的globalSetup在既有页面／详情只读预热后，额外读取英雄／技能目录与首条详情HTML引用的`/_next/static/chunks/`脚本，按URL去重并顺序消费完整响应。开发模式下服务器HTML／RSC就绪不代表浏览器脚本块已编译；此准备不延长原导航断言超时，不改产品数据。 菜单和HoverTooltip在自身事件挂载后提供`data-interactive-ready`标记；首屏键盘聚焦与语言菜单旅程等待对应控件标记，避免把服务端HTML可见当作可交互。等待沿用原断言超时，操作后仍验证原功能结果。 表格浏览还在同一准备阶段读取固定Release的列目录，并以返回的resourceId只读查询一个列值，完成GET／POST接口的首次初始化；校验所选Catalog与资源身份，失败阻止测试启动。此准备不播种浏览器缓存，原浏览用例仍必须在5秒内观察到自己的POST，并核对完整表格、切换复用和DOM上限。

浏览检查在同一次运行中用Playwright原生重试最多一次，仅失败用例进入新worker／浏览器上下文，已通过用例不重复；首次失败、每次尝试、最终flaky或持续失败保留在日志和HTML报告。断言和超时不因重试放宽，持续失败仍阻塞。运行前后的代码／数据身份核对继续有效；变动使整轮过期。独立调用仍核验实时状态，不把动态通过结果跨调用当作缓存。修复改变输入时按受影响范围重新规划。

每项结果保留输入摘要、所用命令、触发理由、状态和耗时；开始执行即落盘，运行中的任务也可定位。收到中断信号先同步保存interrupted及活动任务cancelling，再等待清理并保存cancelled终态。强制终止后仍为cancelling表示清理尚未确认，不能算作完成。并行收据写入顺序执行。输入包括相关源文件、测试、fixture、配置、工具版本和操作系统；内容删除和重命名也改变身份。配置秘密只参与摘要，不写入证据。执行途中或后续任务期间输入改变，结果标为 `stale`，不能作为当前组合的通过结果。

TypeScript 源码检查使用 `tsconfig.check.json`，其增量文件单独存放在 `.medota2/typecheck/`。它不依赖开发 Web 正在重建的 `.next` 类型；Next.js 生成的路由约束由正式构建验证。

共享fixture和独立测试运行器传给Next的配置／产物相对路径，以及生成的tsconfig继承与包含路径，统一使用正斜杠。Windows文件系统路径只在文件操作边界保留原生表示，避免Turbopack无法解析继承配置中的模块别名。

Windows单元测试最多并行4个worker（不超过可用CPU），减少Git和子进程fixture的资源争用；断言与测试时限保持原值。其他平台沿用Vitest默认并发。

独立发布产物使用synthetic-fixture Catalog完成启动检查，构建及smoke环境显式清空本机地图集合／单包路径，防止dotenv重新注入。产物不复制开发地图；正式运行中显式配置的缺失或损坏地图仍按原合同报错。

共享fixture的最终输入核验在测试租约释放和成功收据写入之前执行；runner通过但输入改变时写入`stale`，不能留下`passed`收据。浏览测试更新快照属于输入变更，必须随后进行不更新快照的完整复验。共享与独立测试命令统一剥离最前一个可选`--`分隔符；内部或重复分隔符明确拒绝，防止runner选项被静默解释为测试文件过滤器。

静态检查通过记录可跨调用复用；release自行管理构建产物身份。手工API探针使用Connection:close，避免Playwright跨用例共享空闲TCP与开发服务器关闭连接的竞争；保留请求配置及headers，单次失败直接报告，浏览器网络规则不变。浏览器、数据库检查每次重新确认当前状态；共享页面测试记录 Catalog/Asset 版本，前后版本变化时作废。这里优先用简单、可解释的规则，暂不为动态数据库结果建立复杂缓存。

CI取消相同分支旧运行，保留一个轻量plan入口、core矩阵和按范围估算1至6个browser分片，最后由verify核对所有所选门禁；main在plan已验证同SHA／基线成功候选时跳过空汇总作业。core按现有static／runtime通道在独立主机并行：static执行格式、lint、文档、类型和单元；runtime串行执行所选数据库、基准和正式构建／独立启动。仅生成有任务的通道，完整范围为10个作业，文档只生成static；只有static恢复可复用检查缓存，证据按通道分别上传，任一通道失败仍使core矩阵和末尾汇总失败。两通道并集等于原core，检查范围及输入身份不变；浏览分片先由Playwright列出全部所选任务的当前用例，再按固定版本的历史耗时将跨任务用例统一分配到6片（长用例优先，稳定身份打破并列）。耗时文件仅决定位置；未知／改名用例使用保守默认耗时，条件跳过仍保留。每片用原生test-list选择后再次列举，核对身份集合完全一致，重复身份或选择偏差直接失败；6片并集保持原范围。分片清单、选择摘要、耗时表摘要及实际用例耗时随作业上传，耗时更新须审阅，不能用动态缓存决定本轮范围。每片独立主机、独立测试库、1个worker，单项最多重试一次以保留诊断证据；浏览配置启用failOnFlakyTests，重试后通过也阻断验证，并由失败收据记录该用例供定向复验；失败后取消同轮其他分片。`pnpm check --base REF --lane core`与全部`--lane browser --shard N/6`覆盖原计划，单片不能替代完整CI。每个浏览作业仅安装一次依赖与Chromium、获取一次fixture租约、迁移和seed一次、启动一个受控Next开发服务并预热完整路由一次；旅程、缓存E2E与视觉串行共用该服务，Playwright上下文与报告仍按任务隔离。每项及租约释放前检查输入是否变化；服务异常会取消当前用例，失败与取消均等待所拥有的进程树清理，清理失败同样阻塞。浏览作业不保存无可复用任务的静态检查缓存。未选浏览时6片全部跳过，文档只跑所选core任务。候选快进main仅在精确SHA、原基线、仓库及workflow的成功候选证据匹配后复用；直接推送或证据缺失则执行完整所选计划。候选和直接推送保留入口与末尾汇总；计划失败仍进入汇总并失败，防止应跑任务被错误跳过。操作系统和CI身份参与摘要，不把本机通过记录当作Linux通过记录。覆盖率只在显式`pnpm verify`或`pnpm test:coverage`中启用。

发布快路径让候选CI执行fixture，与本机真实数据检查并行；数据快照变化时调用`check --publication`，本机在选中的真实旅程前追加同范围fixture旅程，CI环境不重复追加。浏览预热按同一规划器给出的旅程范围选择路由，未知范围与跨模块流程保守预热全部；首次目录元信息从轻量head API核对，端口读取工作区登记。输入或计划过期时停止后续任务，并保留stale收据。新增发布协调、依赖防护与恢复合同见[同步Spec](development-data-sync.md#发布候选与执行证据)。

### 发布前预检、定向复验与取消

发布在保存候选提交和导出数据前执行`check --lane static`，范围仍来自完整远端基线；只选择原计划中的静态任务，通过记录由同一指纹复用。完整检查继续包含原计划的所有动态门禁。 CI只读状态查询遇到TLS、连接或网关传输错误时，最多额外重试2次（间隔1秒、2秒），始终校验证书并重新读取同一候选；认证／权限错误、用例失败及写操作不套用该重试，持续连接失败仍阻塞发布。

失败收据保存任务、日志及浏览用例标题。`check --retry-failed <run.json>`按当前代码重新规划，只选择失败任务；存在用例证据时按标题收窄，缺少证据时执行完整失败任务。旅程在本机先核对fixture再核对真实数据，CI使用fixture。收据里的旧命令不直接执行；任务已不在当前计划中或用例改名导致零匹配时阻塞，不能静默通过。定向结果标记为诊断，完整发布仍重新确认全部所选动态检查。

检查批次遇到失败时取消同批其他命令，并等待退出和收据落盘后释放检查锁。受管POSIX命令组先接收SIGTERM，10秒后仍未退出则SIGKILL，退出未确认明确报错；Windows使用本进程创建的子进程树执行taskkill，保留平台复验边界。取消不记为通过，持续失败和stale继续阻塞。

本机非Windows的真实只读旅程使用最多2个worker（不超过可用CPU），每例独立浏览器上下文；fixture和CI仍为单worker。本机完整检查将真实只读旅程与“构建／启动→fixture浏览→数据库合同”两条通道重叠；构建完成即可启动后续fixture浏览，同一fixture通道内仍严格串行。并行构建的自有子进程使用系统below-normal优先级，降低对浏览器交互的CPU争用；不提升已有更低优先级，设置失败仍阻塞检查。基准及未知任务类型位于两条通道完成后的屏障，避免性能测量受并发干扰。新数据publication路径与定向诊断保持串行。每阶段、通道内每项任务前后及最终继续核对输入、完整范围和测试数据身份，取消后不得进入后续任务。本机fixture旅程和E2E同样由runner直接拥有Web进程及进程组，按所选路由预热；Playwright复用该受控服务。取消时先停止并确认Web与测试进程，再释放fixture租约，避免Playwright独立进程组成为遗留服务。

## 共享资源与持久数据

共享测试栈仅在持有test-database锁的一批任务内复用，成功、失败或取消后均在finally中销毁精确测试栈并解除租约，再移除其精确`next`编译目录；诊断、状态及业务数据保留。清理持有test-database锁，核对工作区／目录身份，拒绝活动租约、越界及符号链接，`.keep`继续固定保留；记录删除字节与原因。共享工作台就绪后还尝试执行一次既有测试附件保留策略，锁被占用则延后，避免长期不运行测试时过期附件积累。

日常启动只准备当前所选业务数据库、共享Web与按需计算的小样例；不会预先启动测试库。启动前清理当前checkout的停用容器与网络，须同时匹配Compose工作目录、配置文件、项目和postgres服务；运行中的其他任务及持锁资源保留。禁止全局prune，业务命名卷、镜像、来源、凭据和同步备份保留。

`pnpm dev:stop`和supervisor的SIGINT／SIGTERM／SIGHUP先取消并等待准备命令，等待Web与样例退出，然后对所选业务栈执行不带volumes的Compose down，移除容器及网络；同时回收空闲测试租约、停用资源和符合既有策略的附件。已停止时重复调用也可收尾。清理失败明确报告，锁冲突延后；supervisor被强杀／主机断电无法执行finally，由下次启动补清。`dev:restart`保留数据库以便快速重启；同步切换内部使用`--keep-database`仅停止Web，继续旧库摘要核验。`pnpm dev`保持前台运行，每个终端持有独立租约；关闭终端、Ctrl+C、SIGTERM或SIGHUP释放本终端租约，最后一个退出后supervisor自动调用同一停机流程。租约记录进程及父进程身份和心跳，supervisor每500毫秒检查，进程消失或心跳超过10秒时回收，启动准备期间同样生效。浏览器不持有租约。重启及同步短暂停Web时，原有终端保留租约等待新实例，最多180秒；显式stop结束所有终端。浏览检查和数据同步通过任务范围内的客户端等待就绪，完成或失败即释放，其他开发终端仍可保持服务。

本机任务记录位于 `.medota2/sessions/<id>.md`，每个 Session 只维护自己的文件。涉及同一接口时先读取最新改动，再由一个 Session 整合；常规代码编辑继续并行。

工具使用本机锁排队启动、动态检查、数据库写入、基准和构建。纯静态check不获取全局checks锁，可与其他浏览检查同时执行；类型检查仍持有types锁保护增量缓存，证据独立保存、缓存原子写入。结束时同时核对输入与完整检查计划，文件存在性变化导致计划扩围也标为stale。普通浏览 E2E 使用独立浏览器上下文与独立产物目录。破坏性检查使用批次内共用的test栈，整个过程持有数据库锁；下批重新准备fixture，省去跨任务常驻容器及其启动时间／播种缓存判定。异常中断留下的精确测试租约由下次启动、测试或test:clean持锁回收，清理失败保留租约供重试。

首次 development 初始化只允许在持有 Catalog 锁且没有来源、导入或参考记录时插入 fixture；已有数据直接保留。development seed 仍需精确数据库确认，CLI 只开放 `--if-empty` 路径。Web 物理连接第一次完整验证，后续恢复连接状态并复用验证；其他环境和写入角色仍走完整验证。修改权限或 migration 后重启开发 Web。

生产环境、来源许可、数据提升/回滚规则和秘密配置继续使用各自规范。开发共享与数据库权限是不同层次。

## 计算、产物与可迁移性

小样例输入输出使用带版本的 JSON，并记录输入摘要、字节数、解析耗时及进程峰值内存。基准支持真实来源目录，串行运行并输出输入版本与环境；计时上升先提示复测，不因一次波动阻止日常开发。大型业务任务仍由其领域 Worker 执行；新算法接入时扩展样例入口，而非把重计算放进 Web 请求。

Web 产物放在 `.medota2/releases/<content-key>/`，同一输入复用构建与启动检查。正式产物是该目录下的 `app/`，使用 `.next-release` 缓存构建。显式设置`MEDOTA2_RELEASE_COLD=1`会跳过已验收产物复用，并在release锁内清空`.next-release`（含编译缓存），重新构建与独立启动验收；该执行开关不改变产物身份，成功manifest记录cold。只接受未设置、0或1，非法值直接失败。产物排除本机缓存、状态目录和 dotenv 文件；启动验收使用单独副本注入测试配置，结束后清理。部署时需注入相应运行配置。当前尚无远程部署目标，命令不会发布到外部平台。未来计算组件能独立交付时再增加发布单元。

`next.config.ts` 注册 `scripts/development/build-output.mjs` 的构建完成钩子，在 Next 复制 standalone 前过滤 `.nft.json` 中的本地状态、其他构建、缓存及测试输出引用，路径统一为正斜杠判断，保留当前 dist 的运行文件和正式依赖。此步骤兼容 Next 16.3.3 在 Windows 上排除 glob 与原生路径匹配失败的问题；不修改安装的 Next 包。`release` 在复制前移除 dotenv 并检查产物边界，复制时解引用已追踪的依赖链接为普通文件，避免 Windows 创建符号链接权限要求。失败时清理该次 `app/` 与 smoke 副本，保留构建缓存和小型配置以便诊断。运行及验收入口仍为 `pnpm release`；成功产物含 `manifest.json`，只有目录存在不能视为通过。

文档的职责和更新流向由[文档索引](../README.md#事实归属与更新流向)维护，current只保存活动状态与链接。Claude Code 用薄 `CLAUDE.md` 引用相同文件，OpenCode 用 AGENTS.md 与 `opencode.json` 加载其余入口。更换工具和模型时，用启动、一个小改动和对应检查验证能否接手。

## 自动保留与日志容量

`src/development/storage.ts`集中维护规则；`pnpm release`、共享测试及独立测试Worker结束后调用相同清理入口。清理故障或锁被占用时记录deferred提示，保留原命令结果；CI跳过自动清理，避免验收附件在上传前被移除。手动`pnpm storage:clean`默认只预览，`--apply`重新生成计划并执行，支持`--scope releases`、`tests`或`data-sync`；`pnpm storage:audit`只读盘点整个项目，按目录报告字节及容量告警。

默认保留最近1份且7天内的成功发布目录、最多3份成功测试及2份失败测试完整附件；测试附件共同预算128 MiB。失败／过期／中断结果保护7天，保护期和`.keep`可超过预算并由容量审计提示。已确认诊断完成的目录可用`.resolved`解除保护期，但不会修改原测试状态；终态和完成时间有效的旧记录不再因缺少PID永久豁免。`.keep`固定保留且执行前再次核对。发布记录按builtAt／finishedAt、测试按finishedAt排序，不使用文件修改时间作为版本或成功证据。

清理只移除识别出的已完成发布目录及测试report、test-results、playwright／artifacts、next目录。测试run.json、日志及状态始终保留；共享测试environment.json引用的整个租约目录保留，独立测试须已完成数据库清理且未保留数据库才参与。进程仍存活、无PID／有效时间或数据库未清理的目录保留；共享测试记录为running且PID已退出、startedAt超过保护期时，按中断附件参与回收，原run.json保持原样。执行前再次核对共享租约及运行状态。相同ZIP附件仅在SHA-256一致时去重，保留完整报告副本；每个测试目录的storage-cleanup.json标明清理范围和保留位置。已删除发布的manifest存入.medota2/maintenance/releases/，本轮计划及结果保存在last-storage-cleanup.json。

应用清理按release→test-database→storage的固定顺序获取所需范围锁，避免与构建及数据库复用竞争。候选路径不能越出工作区或穿过符号链接／Windows junction；产物内部的依赖链接计量和删除时只操作链接本身。构建／测试清理不会选择来源、候选、地图、凭据、数据库备份或正在使用的通用编译缓存。同步副本使用独立data-sync锁及[同步回收规则](development-data-sync.md#本地副本与回收)，不对业务数据做年龄删除。release锁内可回收超过512 MiB的`.next-release/cache`，保留正式运行产物；release完成复制及独立启动验收后删除重复的`.next-release/standalone`，保留已验收app与编译cache，保护`.keep`；工作台持锁等待Web退出后回收超过1 GiB的`.next`，保护`.keep`。

本机可在.medota2/storage-policy.json覆盖保留数量和日志容量，字段详见[开发运行手册](../operations/development.md#空间保留与日志)；配置值有范围校验，数量至少1、失败保护期至少1天。MEDOTA2_AUTO_CLEANUP=0禁用自动产物清理，手动清理及日志轮转继续可用。

工作台就绪后及持续运行期间每6小时按独立非阻塞锁尝试构建、测试及同步副本回收；容量审计24小时内最多一次；独立列出`.medota2`各一级目录、依赖、编译缓存和output，未知目录默认256 MiB告警，常用目录使用明确预算。只记录一份最新审计；告警不授权删除业务数据。

工作台supervisor拥有唯一日志写入流，准备命令、Next Web、样例和控制台输出统一通过RotatingLog写入；按默认10 MiB切换，保留当前文件及3份归档。写入时关闭并重开由supervisor持有的文件句柄，子进程不持有日志文件句柄，可在Windows轮转。旧追加日志首次启动按相同容量导入；中断导入留下server.log.import时明确报错保留原文，需先核对该文件后重启。修改日志配置须重启工作台。

## 验收

1. 两次并发 `pnpm dev` 得到同一地址、同一个工作台实例。
2. 保存页面与解析改动，在当前页面看到组合结果；页面参数继续保留。
3. 连续保存、计算失败、修复与取消后，状态和结果版本正确。
4. 文档检查无需产品环境；英雄组件修改只选择对应使用流程。
5. 重复静态检查复用；相关代码、配置或数据变化使旧结果失效。
6. 固定 fixture 覆盖解析 → 保存 → 查询 → 显示，并核对已知移动速度。
7. 测试数据库批次内复用、排队，结束后精确清理；工作台停止后容器／网络回收，再次启动恢复同一业务数据。
8. Web 产物通过启动检查；基准输出可比较输入与测量条件。

## 本机文件地图模式

当机器尚无数据库，只需预览独立地图Dataset时，可设置`MEDOTA2_WORKBENCH_MAPS_ONLY=1`及`DOTA_MAP_COLLECTION_PATH`，并声明`MEDOTA2_ENVIRONMENT=development`、`MEDOTA2_DATA_CLASS=sandbox`。`pnpm dev`／`pnpm dev:restart`复用固定3000服务，验证集合后跳过数据库准备与图鉴预热。页头仅展示地图，入口为`/map`；地图版本通过URL显式选择。

该模式不生成数据库receipt，环境身份仍为unverified，数据库API合同不变；不提供英雄、技能、单位数据。恢复完整工作台时设`MEDOTA2_WORKBENCH_MAPS_ONLY=0`并重启。可执行提取／导入／集合命令见[地图Spec](map-explorer.md)。默认模式行为保持原样。

`hero-map-assets`用途投影属于地图使用流程，检查计划须选择地图算法／组件单测与真实地图旅程；文件hash验证、继承及旧构建未知由`map-hero-assets.test.ts`覆盖。添加模式Hover隔离复用营地旅程，光标图标隐藏与碰撞占地复用视野组件流程。`vision-tile-store`浏览器派生缓存沿用地图检查映射；默认缓存加载／树状态增量与离线逐格等价由`map-vision-client.test.ts`覆盖，裁剪栅格的颜色／方向／世界坐标由`map-vision-panel.test.tsx`覆盖；实际IndexedDB刷新复用和邻格预热随真实地图性能复测核对。

正式产物计算指纹前统一通过`loadLocalEnv`加载本地声明，与`push`一致；单独`release`和发布内构建在输入、运行时及环境一致时可复用同一已验证产物。fixture构建／独立启动覆盖规则保持不变，环境差异仍使证据失效。

浏览检查保留一次失败用例重试；重试后仍失败时以`--max-failures=1`结束本任务并触发既有协同取消。成功的完整检查仍执行所有所选用例。列偏好旅程从已知搜索前缀开始，再输入完整查询；导航旅程从既有antimage查询开始。完整列表、排序、连续滚动及空搜索由独立旅程覆盖，原列设置／持久化／语言／导航断言保留。

检查及正式产物指纹中的`NODE_PATH`按平台分隔符去除完全相同的重复项，保留首次出现的顺序；不同路径、路径顺序及其他环境变量仍参与身份校验。pnpm嵌套调用重复添加相同搜索路径不会再使已通过的静态检查和构建失效。

### CI准备计时与可复现实测

浏览通道的`phases.jsonl`随check run保存，按阶段追加锁等待、数据库准备／迁移／播种、Playwright发现与原生列表回查、Web就绪／预热／停止和数据库回收的毫秒数及通过／失败状态。现有run收据保留实际任务耗时；外层GitHub job记录依赖及浏览器安装。阶段嵌套时不能重复求和；准备失败也保留已完成阶段。

只有一个带明确grep的journeys任务时，按固定历史耗时总和／60秒向上取整为1至6片；复杂、直接测试文件和无已知估算的范围保留6片；历史耗时只估算容量，不筛选用例；分片数只影响分配，所有当前发现用例仍须恰好出现一次。浏览预热合并重复head／目录读取，保留两种语言的replica、固定Release列目录及列值请求。CI保留pnpm原生供应链策略，缓存其registry元数据和验证记录，由pnpm按锁文件内容与策略判定有效性；缓存键包含锁文件、workspace配置和workflow。浏览器安装与测试Compose声明的数据库镜像pull并行，两项都须成功；pull只下载镜像，不创建容器，数据库身份、迁移、播种仍由原租约流程执行。浏览器仅安装现有无channel、headless项目使用的Chromium shell；新增headed/channel测试时须同步安装范围。

`workflow_dispatch`提供auto、full、items、hero-build、map固定诊断范围，full使用检查执行器映射。诊断不能充当发布证据；发布只接受原有push事件、同SHA、同基线及同workflow成功候选。CI比较须分别报告同用例性能和模块用例减少效果，不能将缓存命中或单次主机波动解释为稳定提速。

缓存返回旅程分成两条独立使用流程：详情与历史导航，以及Tab筛选重置与语言刷新。保留原有断言、30秒用例预算和5秒UI断言，避免多段导航累计耗尽单条预算；完整浏览身份由85增至86。新用例继续采用保守默认耗时参与原生分配，不从历史耗时表推断跳过。
