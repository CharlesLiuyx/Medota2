## 使用体验

一个开发者可以同时使用多个 AI Session，共用当前工作目录、分支、开发服务和开发数据。本工作区默认地址为 `http://127.0.0.1:3000/heroes`（已初始化workspace以其origin为准），可以在同一站点内浏览其他页面。任何 Session 保存页面代码，Next.js 自动更新当前页面，尽量保留查看位置、URL 参数和组件状态。框架需要完全重新加载或组件重挂载时，临时组件状态可能重置。

启动时先顺序预热英雄／技能目录、各一条详情路由与浏览器快照接口，再报告共享服务就绪；仅执行只读请求。这样避免第一次点击遇到并发编译／整页热更新而丢失导航。预热失败记录到开发日志，页面仍可使用既有在线路径。

页面右下角的开发面板显示小样例状态、结果版本、移动速度示例、技能数量、耗时和内存。样例直接调用当前生产解析器，默认输入为 `tests/fixtures/vpk/`。首轮目标是预热后的界面约 1 秒、小样例约 2 秒，冷启动单独统计；不能把解析函数耗时当作保存到屏幕的全部延迟。

面板只在共享工作台的开发模式启用，页面可读取 development 或 local-review 数据，生产构建不显示它，开发 API 返回 404。控制操作限制在同源请求，只开放重算和取消。

命令、参数、副作用和配置示例统一由[开发运行手册](../operations/development.md)维护；可执行入口以[package.json](../../package.json)和脚本为准。Codex、Claude Code、OpenCode及普通终端使用同一接口。

## 页面数据与计算样例

`MEDOTA2_WORKBENCH_DATA=auto` 为默认值：已有 local-review 受管环境时，使用现有真实 Catalog 和资产；否则使用 development 数据库，空库才初始化 fixture。可显式选择 `local-review` 或 `development`，修改后重启工作台。所选环境保留原有数据库身份、权限和数据类别，不复制或清空已有数据。

真实预览先调用现有准备入口和资产审计，要求绑定完整、LoD 完整、零 generated fallback。失败明确报错，不静默退回测试样例。页面右下角标明当前数据来源。小样例在独立进程中计算，不影响页面所用的数据集。

浏览器关键流程同时检查头像实际解码和图片响应；真实预览额外要求来源为 exact/alias，禁止将 HTTP 200 的占位图当成头像验收通过。

## 即时反馈

- 页面、组件和样式由 Next.js Turbopack 的 Fast Refresh 更新；共享工作台、独立真实审阅与浏览测试使用相同开发编译器。正式发布构建继续使用既有 webpack 路径。
- Tailwind 只扫描 `src/`；文档、测试及业务数据锁的保存不触发全站样式重编译。新增位于 `src/` 外的界面模板时须显式登记样式来源。
- 开发面板在隐藏标签页暂停轮询，恢复可见时立即读取最新状态；同一面板最多一个请求在途，状态未变不重绘，结果版本变化仍刷新当前页面。
- 解析、领域规则、共享库或 fixture 的文件变化，会合并到一次小样例任务；短时间连续保存使用 180 ms 合并窗口。
- 查询服务变化也触发反馈，并刷新当前路由的数据。解析输入未变时复用计算结果。
- 每次执行使用新的子进程，当前并行上限为 1；旧任务及时取消，回传结果前后检查版本，只有当前任务可以更新显示。
- 启动时或输入未变时，按内容摘要复用样例结果。默认样例无外部网络及数据库写入。
- 错误显示在同页，下一次保存自动重试。计算期间保留上一结果并明确标记过期。
- 迁移及运行配置变化显示待准备原因，运行 `pnpm dev:restart` 后恢复。持久数据不会在日常重启中清空。

## 数据库读取与故障恢复

共享工作台无论读取development还是local-review，都只对每个物理Web/read连接首次完整审计；每次借用恢复会话基线、检查角色及只读事务，新连接重新验证。独立审阅入口、test／production和写入操作不复用审计。权限、迁移及连接实现变更后运行`pnpm dev:restart`。

连接池空闲断线不终止Web进程；读取中断废弃故障连接，后续请求重连。错误仅保留timeout／unreachable／capacity／unknown分类，不暴露数据库URL、驱动原文或凭据。变化页的预期连接失败显示页内重试入口并保留全局导航，重试保持URL条件；根布局版本索引读取失败退回未验证状态。身份不符、权限漂移、非法版本与程序错误仍按原合同处理。

## 按需验证与 CI

`scripts/development/check-plan.mjs` 是唯一范围规则，同时供本地和 CI 使用。它只使用 Node 内置能力，CI 可以在安装浏览器和准备数据库前规划。

规则按模块维护：文档检查格式、链接／锚点、命令与入口；地图文件／算法／组件选已有地图专项；地图UI和视野场景读取另选`map:`浏览旅程（真实地图版本、Worker、取消、语种及窄屏；来源类型、Esc选中／占格、反隐高亮与英雄图标搜索），无地图的fixture明确跳过该真实数据旅程，合成场景由单测覆盖；单位选单位专项及使用流程。Hero／Ability解析继续核对已知答案，持久化变化加入数据库检查；共享基础和未知影响范围保守扩大，数据库合同／迁移执行完整隔离合同，工具链扩大到单测与构建。纯文件地图不默认启动产品数据库，涉及Catalog读取的地图服务仍检查数据库依赖。英雄小地图图标清单／导入器／只读图片入口触发地图旅程和图片专项；未收窄的持久化依赖仍扩大验证。日常UI更改不构建完整Web。

局部任务默认使用范围卡的 `--files` 集合，混合修改按范围并集验证；组合交付才检查全部未提交改动或 `--base`。登记的无交互展示组件与静态翻译资源使用现有组件／资源测试：当前包括 DatasetBadge、en.json、zh-CN.json、official-terms.json；规划器自身使用范围边界测试。发布CLI的push入口及publication目录内已登记的候选、收据、工作流和CI模块使用发布故障专项；导出器、未知新增模块或专项缺失仍扩大检查。登记依据是职责与已有测试，不按“改动行数少”推断安全；组件新增交互／数据读取时移出该登记。登记源或对应测试缺失时退回保守规则，未知文件、删除、运行器及构建工具变更继续扩大。

浏览流程以明确的标题前缀区分地图、目录、悬停、版本导航、变化页、语言及名称，避免 `heroes` 子串把所有流程一起选中。语言资源只验证消息覆盖、词汇与插值，语言解析／Provider／proxy改变仍验证语言切换与跨页面流程。新增或改名journey直接触发全部旅程，确保未登记标题也被执行。

浏览器测试的globalSetup在既有页面／详情只读预热后，额外读取英雄／技能目录与首条详情HTML引用的`/_next/static/chunks/`脚本，按URL去重并顺序消费完整响应。开发模式下服务器HTML／RSC就绪不代表浏览器脚本块已编译；此准备不延长原导航断言超时，不改产品数据。

浏览检查在同一次运行中用Playwright原生重试最多一次，仅失败用例进入新worker／浏览器上下文，已通过用例不重复；首次失败、每次尝试、最终flaky或持续失败保留在日志和HTML报告。断言和超时不因重试放宽，持续失败仍阻塞。运行前后的代码／数据身份核对继续有效；变动使整轮过期。独立调用仍核验实时状态，不把动态通过结果跨调用当作缓存。修复改变输入时按受影响范围重新规划。

每项结果保留输入摘要、所用命令、触发理由、状态和耗时。输入包括相关源文件、测试、fixture、配置、工具版本和操作系统；内容删除和重命名也改变身份。配置秘密只参与摘要，不写入证据。执行途中或后续任务期间输入改变，结果标为 `stale`，不能作为当前组合的通过结果。

TypeScript 源码检查使用 `tsconfig.check.json`，其增量文件单独存放在 `.medota2/typecheck/`。它不依赖开发 Web 正在重建的 `.next` 类型；Next.js 生成的路由约束由正式构建验证。

共享fixture和独立测试运行器传给Next的配置／产物相对路径，以及生成的tsconfig继承与包含路径，统一使用正斜杠。Windows文件系统路径只在文件操作边界保留原生表示，避免Turbopack无法解析继承配置中的模块别名。

Windows单元测试最多并行4个worker（不超过可用CPU），减少Git和子进程fixture的资源争用；断言与测试时限保持原值。其他平台沿用Vitest默认并发。

静态检查通过记录可跨调用复用；release自行管理构建产物身份。浏览器、数据库检查每次重新确认当前状态；共享页面测试记录 Catalog/Asset 版本，前后版本变化时作废。这里优先用简单、可解释的规则，暂不为动态数据库结果建立复杂缓存。

CI 取消相同分支旧运行，按规划安装 Chromium，调用相同的 `pnpm check --base REF`。操作系统和 CI 身份参与摘要，不把本机通过记录当作 Linux CI 的通过记录。覆盖率只在显式 `pnpm verify` 或 `pnpm test:coverage` 中启用。

发布入口调用`check --publication`：本机在选中的真实旅程前追加同范围fixture旅程，CI环境不重复追加。浏览预热按同一规划器给出的旅程范围选择路由，未知范围与跨模块流程保守预热全部；首次目录元信息从轻量head API核对，端口读取工作区登记。输入或计划过期时停止后续任务，并保留stale收据。新增发布协调、依赖防护与恢复合同见[同步Spec](development-data-sync.md#发布候选与执行证据)。

## 共享资源与持久数据

本机任务记录位于 `.medota2/sessions/<id>.md`，每个 Session 只维护自己的文件。涉及同一接口时先读取最新改动，再由一个 Session 整合；常规代码编辑继续并行。

工具使用本机锁排队启动、动态检查、数据库写入、基准和构建。纯静态check不获取全局checks锁，可与其他浏览检查同时执行；类型检查仍持有types锁保护增量缓存，证据独立保存、缓存原子写入。结束时同时核对输入与完整检查计划，文件存在性变化导致计划扩围也标为stale。普通浏览 E2E 使用独立浏览器上下文与独立产物目录。破坏性检查使用一个可复用的 test 栈，整个过程持有数据库锁。Docker 重启导致 tmpfs 丢失时，只替换已记录的测试栈；development 和 local-review 数据保持不动。

首次 development 初始化只允许在持有 Catalog 锁且没有来源、导入或参考记录时插入 fixture；已有数据直接保留。development seed 仍需精确数据库确认，CLI 只开放 `--if-empty` 路径。Web 物理连接第一次完整验证，后续恢复连接状态并复用验证；其他环境和写入角色仍走完整验证。修改权限或 migration 后重启开发 Web。

生产环境、来源许可、数据提升/回滚规则和秘密配置继续使用各自规范。开发共享与数据库权限是不同层次。

## 计算、产物与可迁移性

小样例输入输出使用带版本的 JSON，并记录输入摘要、字节数、解析耗时及进程峰值内存。基准支持真实来源目录，串行运行并输出输入版本与环境；计时上升先提示复测，不因一次波动阻止日常开发。大型业务任务仍由其领域 Worker 执行；新算法接入时扩展样例入口，而非把重计算放进 Web 请求。

Web 产物放在 `.medota2/releases/<content-key>/`，同一输入复用构建与启动检查。正式产物是该目录下的 `app/`，使用 `.next-release` 缓存构建。产物排除本机缓存、状态目录和 dotenv 文件；启动验收使用单独副本注入测试配置，结束后清理。部署时需注入相应运行配置。当前尚无远程部署目标，命令不会发布到外部平台。未来计算组件能独立交付时再增加发布单元。

`next.config.ts` 注册 `scripts/development/build-output.mjs` 的构建完成钩子，在 Next 复制 standalone 前过滤 `.nft.json` 中的本地状态、其他构建、缓存及测试输出引用，路径统一为正斜杠判断，保留当前 dist 的运行文件和正式依赖。此步骤兼容 Next 16.3.3 在 Windows 上排除 glob 与原生路径匹配失败的问题；不修改安装的 Next 包。`release` 在复制前移除 dotenv 并检查产物边界，复制时解引用已追踪的依赖链接为普通文件，避免 Windows 创建符号链接权限要求。失败时清理该次 `app/` 与 smoke 副本，保留构建缓存和小型配置以便诊断。运行及验收入口仍为 `pnpm release`；成功产物含 `manifest.json`，只有目录存在不能视为通过。

文档的职责和更新流向由[文档索引](../README.md#事实归属与更新流向)维护，current只保存活动状态与链接。Claude Code 用薄 `CLAUDE.md` 引用相同文件，OpenCode 用 AGENTS.md 与 `opencode.json` 加载其余入口。更换工具和模型时，用启动、一个小改动和对应检查验证能否接手。

## 自动保留与日志容量

`src/development/storage.ts`集中维护规则；`pnpm release`、共享测试及独立测试Worker结束后调用相同清理入口。清理故障或锁被占用时记录deferred提示，保留原命令结果；CI跳过自动清理，避免验收附件在上传前被移除。手动`pnpm storage:clean`默认只预览，`--apply`重新生成计划并执行，支持`--scope releases`或`tests`。

默认保留最近2份成功发布目录、10份成功测试完整附件，失败／过期／中断结果至少保留7天及最近5份。`.keep`固定保留且执行前再次核对；既有缺少PID元数据的失败记录按未解决证据保留，显式添加`.resolved`后参与正常保留规则。发布记录按builtAt／finishedAt、测试按finishedAt排序，不使用文件修改时间作为版本或成功证据。

清理只移除识别出的已完成发布目录及测试report、test-results、playwright／artifacts、next目录。测试run.json、日志及状态始终保留；共享测试environment.json引用的整个租约目录保留，独立测试须已完成数据库清理且未保留数据库才参与。运行中或没有可识别完成记录的目录保留。相同ZIP附件仅在SHA-256一致时去重，保留完整报告副本；每个测试目录的storage-cleanup.json标明清理范围和保留位置。已删除发布的manifest存入.medota2/maintenance/releases/，本轮计划及结果保存在last-storage-cleanup.json。

应用清理按release→test-database→storage的固定顺序获取所需范围锁，避免与构建及数据库复用竞争。候选路径不能越出工作区或穿过符号链接／Windows junction；产物内部的依赖链接计量和删除时只操作链接本身。清理不会选择来源、同步数据、候选、地图、凭据、数据库备份或正在使用的通用编译缓存。

本机可在.medota2/storage-policy.json覆盖保留数量和日志容量，字段详见[开发运行手册](../operations/development.md#空间保留与日志)；配置值有范围校验，数量至少1、失败保护期至少1天。MEDOTA2_AUTO_CLEANUP=0禁用自动产物清理，手动清理及日志轮转继续可用。

工作台supervisor拥有唯一日志写入流，准备命令、Next Web、样例和控制台输出统一通过RotatingLog写入；按默认10 MiB切换，保留当前文件及3份归档。写入时关闭并重开由supervisor持有的文件句柄，子进程不持有日志文件句柄，可在Windows轮转。旧追加日志首次启动按相同容量导入；中断导入留下server.log.import时明确报错保留原文，需先核对该文件后重启。修改日志配置须重启工作台。

## 验收

1. 两次并发 `pnpm dev` 得到同一地址、同一个工作台实例。
2. 保存页面与解析改动，在当前页面看到组合结果；页面参数继续保留。
3. 连续保存、计算失败、修复与取消后，状态和结果版本正确。
4. 文档检查无需产品环境；英雄组件修改只选择对应使用流程。
5. 重复静态检查复用；相关代码、配置或数据变化使旧结果失效。
6. 固定 fixture 覆盖解析 → 保存 → 查询 → 显示，并核对已知移动速度。
7. 测试数据库可以复用、排队和精确清理，已有开发数据保持不动。
8. Web 产物通过启动检查；基准输出可比较输入与测量条件。

## 本机文件地图模式

当机器尚无数据库，只需预览独立地图Dataset时，可设置`MEDOTA2_WORKBENCH_MAPS_ONLY=1`及`DOTA_MAP_COLLECTION_PATH`，并声明`MEDOTA2_ENVIRONMENT=development`、`MEDOTA2_DATA_CLASS=sandbox`。`pnpm dev`／`pnpm dev:restart`复用固定3000服务，验证集合后跳过数据库准备与图鉴预热。页头仅展示地图，入口为`/map`；地图版本通过URL显式选择。

该模式不生成数据库receipt，环境身份仍为unverified，数据库API合同不变；不提供英雄、技能、单位数据。恢复完整工作台时设`MEDOTA2_WORKBENCH_MAPS_ONLY=0`并重启。可执行提取／导入／集合命令见[地图Spec](map-explorer.md)。默认模式行为保持原样。

`hero-map-assets`用途投影属于地图使用流程，检查计划须选择地图算法／组件单测与真实地图旅程；文件hash验证、继承及旧构建未知由`map-hero-assets.test.ts`覆盖。添加模式Hover隔离复用营地旅程，光标图标隐藏与碰撞占地复用视野组件流程。`vision-tile-store`浏览器派生缓存沿用地图检查映射；默认缓存加载／树状态增量与离线逐格等价由`map-vision-client.test.ts`覆盖，裁剪栅格的颜色／方向／世界坐标由`map-vision-panel.test.tsx`覆盖；实际IndexedDB刷新复用和邻格预热随真实地图性能复测核对。
