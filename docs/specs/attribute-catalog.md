# 属性图鉴

## 身份与关系

属性成为独立只读领域实体，入口 `/attributes` 与 `/attributes/[id]`，顶栏位于物品之后。稳定语义身份与所选 Catalog 组成版本内身份；通用字段使用审阅过的别名映射，无法确认同义关系的参数使用 `实体类型~对象身份~字段`。同名字段不自动合并，例如技能的 bonus_damage 不自动视作普通攻击力。

英雄基础值及成长、单位基础字段、物品 AbilityValues／旧 AbilitySpecial 与冷却／魔耗／距离、技能参数及顶层基础数值均保留引用。关系记录对象、字段、来源路径、可得行号、原值、条件、所选版本；对象名称沿用同版目录。本页不把引用值求和，不把定义存在当作当前比赛可用；天赋、命石、升级修正保留来源条件，通过所属技能继续导航。

既有物品、英雄、技能、单位的数值标签以及实体简述卡内属性，统一使用带行内图标的属性实体引用，可悬停阅读简述、点击进入详情；卡内嵌套属性卡保留父卡。稳定属性／对象专属参数仍按attributeId映射，版本值等非游戏属性元信息不伪造实体。属性关联列表回到所属对象。URL、顶栏及 API 固定同一 Release，历史来源缺失显式提示，未知身份返回未找到。详情保留属性间的机制关联。

### 悬浮卡中的计算说明

属性实体卡片打开时，通过`/api/attributes/preview`按当前固定Release、属性身份读取同版公式、依据和适用范围。当前格的原始数值一并传递，已审阅版本的力量／敏捷／智力单值给出具体基础贡献，例如24力量对应528生命上限与2.4点/秒生命恢复；成长字段标为每级贡献。展示精度不改变计算输入。多等级向量、未知参数、未审阅版本不套用单值计算，未有已核对公式时明确说明；失败可重试，版本切换取消旧读取。不把基础贡献当成总面板，不推断主属性伤害、装备叠加、增幅或技能覆盖。

## 官方名称与展示

名称优先使用同提交的 `dota_ability_variable_*` 与明确的官方名称 token。`+$armor` 等引用先展开，再去展示符号，不能直接显示 armor。语言选择沿用全局 zh-CN／en；不改变来源名字。夜间视野使用官方天赋／银月之晶文本中的“夜间视野”，与白天视野相邻；力量、敏捷、智力组成独立“基础属性”组。

目录默认通用属性，可切换全部属性与专属参数，支持中文、英文、内部身份、关联对象与属性拼音检索，URL恢复筛选。普通属性每批48项，首批另外包含搜索命中的基础三属性（最多3项），确保2／3／4列布局跨批完整衔接；批次间距与卡片行距均为4px。不把全部专属参数嵌入首屏；游标绑定版本、查询、范围和模型版本，拒绝跨查询使用。搜索合并80ms请求，取消旧请求，失败可重试；沿用 InfiniteList 的上下视口加载和回收规则。关联列表支持对象类型与名称筛选。

施法前摇、施法后摇、持续施法时间按此顺序相邻。攻击／施法后摇即使尚无完整时长也保留概念入口；未知数值不填零。

目录标题行以信息图标的 HoverTooltip 展示用途与版本说明，支持悬停、键盘聚焦、点击和 Escape 收起。宽屏将搜索框、属性数量／加载状态、范围及清除筛选整组放在标题行右侧；属性统计以“当前筛选数 / 全部属性数”显示，分母包含所选版本全部通用属性与专属参数，不随搜索或范围变化；搜索框宽屏约240px，跟随其他图鉴采用透明底色、左侧搜索图标和统一文字留白。统计始终位于搜索框右侧，窄屏将搜索组及范围与清除筛选控件依次换行，不挤压统计或造成页面横向溢出。

属性详情的含义、范围、效果说明、枚举解释、公式备注和VPK说明正文中，已确认的通用属性名称显示金色下划线实体链接，点击保留Release与语言。采用同版名称和明确别名，优先匹配覆盖完整术语的长名称；例如“生命值上限”“技能伤害增强”“冷却时间降低”不拆成短词。魔法伤害、物理伤害、纯粹伤害匹配同版“伤害类型”的对应枚举值，普通／弱驱散和强驱散进入同版“驱散类型”的对应解释；链接带枚举锚点，未收录取值不生成该枚举链接。仅登记明确复合措辞，不把“魔法”“物理”等裸词自动当作枚举。英文（含中文说明中的英文名称）按完整单词匹配，词边界参与候选选择；歧义名称整体保持原文，重复出现同一候选不能解除歧义，专属参数不参与通用词匹配。原始措辞、数值、换行、证据等级与来源token不改变，文本引用不表示来源数值已经引擎验证。

每种属性展示含义、适用范围、同版引用、机制依据和已知公式。对象专属参数展示其所属对象完整效果说明；没有可靠证据时明确单位／结算待核验，不能编造机制。内部字段、条件和来源记录收在可展开依据中。

### 未命名参数的逐项来源查询

`src/data/attribute-parameters/supplement.v1.json` 记录按固定 source commit／技能身份／字段审阅的双语名称；`unresolved.v1.json` 保存每个仍待确认的身份、字段定义行、标签与说明查询结果及原因。正常同版官方标签优先，再使用审阅补充；不把其他对象的同名字段标签直接套用，也不改变属性身份或数值。补充资源仅由服务端只读模型加载，不进入属性客户端组件。

逐项搜索中英官方参数 token（包含注释与 `:n` 后缀）、技能效果／命石／神杖／魔晶／注释说明中的 `%field%` 和 `{s:field}`，结合实际字段定义核对。资源区分官方标签、注释标签、效果说明与字段释义，保存来源文件 SHA-256、定义行／文本行／token、客户端版本、提取时间和实现版本。注释可能过时；字段释义仅解释字段，不证明单位、实际玩法或引擎结算。说明必须归属于对应技能，长技能身份优先匹配，不能误借名称前缀相似的辅助技能。

例如星破天惊的 `movespeed_bonus_duration` 按同版说明命名为“攻击速度加成持续时间”；网线的 `count` 为“网线数量上限”，不能套用物品的“额外攻击目标数”。对应来源和待核验说明放在“字段与条件依据”中。缺少直接标签的参数可按用户授权，结合变量名、所属技能说明及相邻属性推定可读名称；上下文推定不改变属性身份，不合并同名字段，也不视为官方命名或机制核验。

首轮[来源查询](../history/2026-10-08-attribute-parameter-labels.md)补充7.41e／6918的1,647项及7.41f／6944的1,646项。后续用户授权GPT-6-Luna子代理结合变量与技能上下文，为剩余1,840／1,846项逐项确定中英名称；名称显示覆盖全部3,487／3,492项原缺名。`contextual-labels.tsv`记录精确技能／字段绑定、双语名称、把握程度与理由，生成器保存同版名称／效果说明来源及字段定义。依据展开处标明“上下文推定”、模型、把握程度及核验边界；取得明确官方或实现证据后可逐项替换。完整结果见[上下文命名记录](../history/2026-10-08-attribute-context-names.md)。

复跑：`pnpm exec tsx scripts/analysis/build-attribute-parameter-labels.ts <source-Git-repository> --check`。脚本使用已有英雄／技能解析器，从两份固定Git对象重新构建全部缺名清单、名称绑定与查询证据，校验资源实际内容及摘要；不读取外部工作树改动，也不写业务数据。省略 `--check` 根据已审阅词汇及上下文推定TSV重新生成两份JSON。新版本不会自动继承这些名称。属性只读模型与查询游标分别采用 `attribute-read-model-v4` 与 `attributes-v5`，旧游标必须重新查询。

### 英文原变量名的中文名称

中文属性标题或关联标签仍为`AbilityType`、`MaxLevel`等英文变量时，使用独立的`field-labels.tsv`及`field-labels.v1.json`中文词汇。`field-bindings.v1.json`固定两版实际读取的对象／字段集合与上下文样本，读取层仅为已审阅commit、对象类型、对象身份和原始字段精确命中的英文标签补中文；已有中文、英文展示名称、属性身份、数值、枚举与条件均保持原定义。

标准根字段按对象类型和字段共享名称，例如技能`AbilityType`为“技能类型”、`MaxLevel`为“技能最高等级”；物品库存字段按初始数量、数量上限、初始时间、恢复时间分别命名。少数仍为英文的技能专属数值字段按技能身份隔离，例如米波`range`为“投掷作用距离”，不借给其他技能。同名中文名称不会合并属性身份。

用户授权三个GPT-6-Luna子代理并行复核全部102项词汇。每版13,355个英文原变量标题已补为中文，同时覆盖7.41e／7.41f的30,761／30,758处英文关联标签。所有词汇保存把握程度与理由，依据展开处明确中文名称为上下文推定；支持修正和施法超出距离等模糊字段使用中性名称，不把释义视为引擎机制验证。模型资源仅在服务端读取。

复跑：`pnpm exec tsx scripts/analysis/build-attribute-field-labels.ts <source-Git-repository> --check`。生成器从固定Git对象重建来源hash，用已有英雄／技能解析器、单位继承与物品定义逐项验证全部对象／字段存在，核对词汇覆盖、归一化英雄列、客户端版本、绑定总数和资源实际摘要；省略`--check`按已审阅词汇与绑定重新生成名称资源。新来源、对象或字段不自动继承；需要重新盘点、审阅与更新绑定。审阅与验收见[中文字段命名记录](../history/2026-10-08-attribute-field-chinese-names.md)。

## 类型、枚举值与覆盖

属性区分数值、单选枚举与可组合标记。驱散类型保留 `SPELL_DISPELLABLE_YES`、`SPELL_DISPELLABLE_YES_STRONG`、`SPELL_DISPELLABLE_NO` 的原值、名称、含义及关联数量；这是效果能否被驱散，不是技能提供什么驱散。伤害类型、减益免疫、目标阵营／类型／标记、技能行为、主属性、攻击／移动／防御类别使用相同模型。组合标记逐值展示和筛选，未知枚举值保留原值并标为待核验；缺字段不能推断默认枚举。

四类对象详情的“完整属性引用”补充全部已收录数值与枚举链接。根级数字字段由 `attribute-fields.ts` 逐项记为属性或身份／展示／行为元数据；未识别的新数字字段保留专属参数。单位继承默认与父定义的字段并保留来源行。技能与物品保留全部 AbilityValues／旧 AbilitySpecial 及条件；同版官方 `$` 变量为明确语义映射的额外依据。符号枚举根字段（DOTA／SPELL／DAMAGE／ABILITY_TYPE）也保留；通知展示文字不作为属性。枚举主属性类型与数值主属性加成不合并。

[字段审计](../data/attribute-coverage-7.41e-7.41f.json)覆盖两份固定提交：每版根级数值键分别为英雄68、技能58、单位74、物品67，逐键记录处置与示例来源；物品每版1780处 AbilityValues 数值均已检查进入适配结果。该审计说明公开定义字段的处理覆盖，不声称模型资源、引擎内部状态或全部游戏机制已穷尽。

复跑：`pnpm exec tsx scripts/analysis/audit-attribute-coverage.ts <source-Git-repository>`，参数为含两份固定提交的只读Git来源。脚本通过Git对象读取，输出上述版本化审计JSON，不读取工作树改动、不改业务数据。新版本须重做字段／枚举盘点，增加来源版本和未证实机制的核验项。

## 证据与计算

`src/data/attributes/evidence.v1.json` 保存经过选择的固定 Git 文本及文件hash、行号、版本、导入时间和提取器／schema版本；不复制整个外部仓库。已审阅 7.41e／6918 与7.41f／6944，其他提交不自动套用这些公式。

证据分为：同版 VPK 定义、官方说明、基于说明的有限数学推导、社区机制参考与待引擎核验。官方文本也可能过时：`DOTA_StatTooltip_*Bonus` 的旧系数与 `DOTA_HeroStats_*_Desc` 冲突时同时记录，采用后者作为面板说明依据，仍不宣称已执行引擎验证。旧视野词条的夜间占位符重复引用白天字段，不能从该文本猜出夜间数值。

三属性贡献按同版面板说明推导：力量每点22生命与0.1生命恢复；敏捷每点0.16护甲与1攻速；智力每点12魔法、0.05魔法恢复与0.1个百分点基础魔抗。只表示基础贡献，排除增幅与技能覆盖。

护甲公式和攻速／基础攻击间隔公式显示社区依据及限制。护甲示例包含负护甲，不包括格挡、攻击防御类型与其他修正。比例类公式只作用于已结算的单个有效比例，不推断多来源叠加；特殊来源如巫毒面具的伤害排除备注保留原文，不推广到所有技能吸血。

社区参考：[护甲](https://liquipedia.net/dota2/Armor)、[攻击速度](https://liquipedia.net/dota2/Attack_Speed)，查阅2026-10-07。搜索可读取机制片段，护甲正文直接访问返回403；因此不把网络片段标为同版实测证据。未确认项交由[Windows核验任务](../work/attribute-engine-verification.md)。

### 英雄等级基础面板

英雄详情使用`src/presentation/hero-stats.ts`，只为上述两份已审阅source commit计算基础面板，并叠加已映射的天赋、物品／状态及技能修饰。生命＝基础生命＋22×力量；生命恢复＝基础恢复＋0.1×力量；魔法＝基础魔法＋12×智力；魔法恢复＝基础恢复＋0.05×智力；护甲＝基础护甲＋0.16×敏捷；攻速＝基础攻速＋敏捷；基础魔抗＝来源魔抗＋0.1×智力（百分点）。物品与状态可提供百分比修饰；普通攻速限定20–700、移速100–550。特殊英雄技能突破边界仍需单独建模。

普通主属性英雄的攻击上下限分别加上主属性；两份固定来源的`resource/localization/dota_english.txt`中`DOTA_StatTooltip_PrimaryBonus`说明每点主属性提供1攻击力，文件hash沿用evidence.v1.json中对应快照。全才攻击上下限增加三围之和×0.45，依据[Valve 7.38补丁](https://www.dota2.com/patches/7.38)，官方[datafeed](https://www.dota2.com/datafeed/patchnotes?version=7.38&language=english)于2026-10-13读取确认系数从0.7降低到0.45；规则仅绑定当前已审阅7.41e／7.41f，不自动外推到未来或未知版本。以上属于来源说明推导，仍保留同版引擎核验边界。

输入使用完整精度，结果消除浮点尾差后复用数值格式化；缺失值保留空值，未知主属性不猜攻击加成。所有受缺失成长影响的派生项在非1级显示缺项，其他可计算项仍可用。原始属性链接保留同版定义；图条比较同一英雄的等级成长，不代表不同英雄间排名或当前剩余资源。

### 属性数值的全英雄排名

排序分布图使用自实现HTML浮层显示悬停柱条的英雄名与数值，移入立即出现、横向移动即时切换并高亮该柱条、离开隐藏；不使用SVG title或原生title延迟提示。每图一个局部提示与统一指针入口，已有排序结果不因悬停重算或请求网络；浮层在图宽内避让且不截获鼠标，保持父排名卡可进入。图表可聚焦，左右方向键、Home／End切换英雄，触控点击定位，Escape沿用父卡关闭。

英雄属性面板中的实际数值（三围／每级成长、派生数值与恢复、攻击区间两端、来源基础值、附加属性）可悬停、聚焦或点击查看排名浮层。读取与详情页相同不可变Catalog的全英雄必要数值列，页面加载时批量提供，不在Hover时请求数据。等级改变时复用同一`heroStatsAtLevel`计算全英雄同等级基础面板；对照英雄无装备、天赋及技能加成，当前英雄使用当前配置并替换其对照样本，避免重复计数。浮层明确该口径，原始基础字段仍比较原始值；未知／缺失保持空值并排除，标明可比人数，未审阅来源不补造派生值。

按数值从高到低排序（不是战斗优劣），并列为1＋严格大于当前值的人数。整数分位P＝round(100×严格小于当前值的人数÷与当前值不同的人数)；最高P100、最低P0，全体同值／单一样本为P50并显示并列。SVG按全部有效英雄排序绘制数值条，金色线和点标出当前英雄，保留负值和零值；展示精度不参与排序。攻击区间分别展示上下限，不以未说明的平均数替代。

三围及由三围成长派生的生命／魔法／两类恢复／攻击／护甲／攻速／魔抗，追加每级增量的同口径排名与分布。增量为保持当前配置不变的L→L+1差值，30级使用29→30；不假定同时升级技能或选择天赋。固定来源值无增长卡；三围成长数字自身只显示其成长值排名。全英雄等级投影按Catalog数据与等级记忆化，Hover只对已有数值排序和绘制，当前配置更改仅重算当前英雄。

### 计算说明与属性关联

`hero-stats-expression`的数值表达式同时用于求值和展示，保持现有取整、加成顺序、范围限制与来源门禁；`heroStatsAtLevel`返回数值和同一表达式，无独立说明公式。计算结果使用金色属性语义图标，悬停／聚焦／点击显示公式、当前代入值、结果及输入表；攻击区间说明包含两端。公式输入列保持聚合修饰；逐来源归因使用下述同一求值器的阶段差额，不解析物品描述；独立叠加魔抗／闪避／冷却修饰逐项列出。缺项显示“—”和原因，不补造来源。

`HeroCalculationScope`仅维护页面内活动属性；计算浮层打开时，高亮直接及传递输入、依赖该属性的计算项与常显来源行，关闭／Escape／卸载解除。来源行悬停／聚焦也高亮依赖它的计算项。基础攻击间隔依赖来源`attack_rate`及对应百分比修饰，不错误关联攻击速度；等级关联三围及其下游。关联状态局限于说明组件，不触发装备或技能重新投影。

六项属性条在存在装备／状态贡献时分段：基础段包含当前等级、天赋与未升级的已学技能；库存先按唯一组与攻击类型筛出实际生效修饰，再按槽位→中立→附魔→消费状态逐步求值，以相邻阶段差额归因。神杖／魔晶来源同时触发已建模技能的升级变化；重复升级仅首次生效。乘法项的交互量归入后计入来源，不能把该差额解释为移除单件后的独立变化。分段带符号合计必须等于当前总值；未知值不归零，未建模效果不绘制。

颜色沿用各属性原色，基础深色、各来源交替明显深浅，边界独立描边；负贡献用同色斜纹覆盖被扣减区间，尺度包含所有中间值及最终值。原100／1000刻度和1秒恢复淡色段保留。每段自实现Hover展示来源、贡献、前后数值，装备／状态详情附面板贡献；双向关联来源对象、分段及相关计算属性。所有阶段按配置记忆化，Hover只更新关联状态，不取数或重新投影。分段按钮与无障碍meter为同级，保留键盘访问。

### 天赋修饰与组合状态

天赋必须来自当前英雄同版有效绑定。`hero-talents`将经过审阅的通用身份映射到类型化修饰，值只读取同版唯一、无附加条件的`value`行。力量／敏捷／智力／全属性、生命／魔法、两类恢复、攻击力／基础攻击力、护甲、攻速、移速、攻击距离与昼夜视野分别映射；例如`special_bonus_mp_regen_150`读取实际值1.5，不把身份尾缀150作为数值。双属性天赋可生成两个修饰，攻击力两端同步变化。`hero-build`只存英雄等级与有序选择ID，规范化时剔除未知、重复、等级失效及超额选择；界面不负责推导效果。

先叠加三围再推导基础面板，之后合并固定数值修饰；移速百分比与魔法恢复增幅作用于固定加成后的数值。普通额外魔抗采用剩余伤害相乘：`R = 1 - (1 - Rbase) × Π(1 - Rtalent)`，不将15%天赋直接当作15个百分点；依据[魔抗机制资料](https://liquipedia.net/dota2/Magic_Resistance)，2026-10-13查阅，属于社区机制参考，仍待同版引擎复核。所有效果保留当前来源commit门禁；不能推广到来源未知的版本、特定技能覆盖或负面减抗机制。

适配未匹配时，若在同英雄技能参数中发现对应天赋modifier，标为技能／条件效果；否则标为当前未纳入属性计算。两者均不自动增加基础面板，技能卡通过同版AbilityValues天赋modifier联动当前技能等级的参数及文案；来源条件无法解析时明确缺项，详见[语义UI](semantic-game-ui.md#英雄详情布局与等级)。物品投影已补充闪避、吸血、施法距离、冷却缩减及附魔附加属性；天赋未适配部分仍明确标记；扩展时新增语义适配与计算，不解析本地化文案。没有可靠标量、存在条件modifier或多值冲突时不计算，保留天赋详情入口。

来源核对：两份固定VPK的`npc_abilities.txt`及对应`abilities_english.txt`确认通用天赋身份、值与单位；7.41f中的力量15、魔法恢复1.5、基础攻击25、魔抗10／15等直接值均来自AbilityValues。二次天赋解锁采用[Valve 7.29补丁](https://www.dota2.com/patches/7.29)及其[官方datafeed](https://www.dota2.com/datafeed/patchnotes?version=7.29&language=english)，2026-10-13读取确认27／28／29／30级对应10／15／20／25级的剩余天赋。技能与天赋组合现共享技能点预算，详见[技能等级联动](semantic-game-ui.md#英雄详情布局与等级)；全属性额外加点尚未模拟。

### 物品、状态与附魔修饰

来源字段映射、阶段顺序、唯一效果、消费状态及中立池规则见[英雄物品和状态](hero-inventory.md)。负面智力影响魔法与魔抗；百分比攻速作用于当前攻速；附魔BAT与视野减少分别作用于对应面板。装备、状态和附魔贡献进入同一纯投影，移除即恢复。

## 存储与边界

复用不可变 Catalog 的英雄／技能定义，以及校验 steam.inf 的同提交单位／物品只读模型；不新增数据库迁移或 head。最多缓存两版成功构建的只读索引，来源缺失／构建失败不永久缓存。物品适配器 v4 保留字段身份、行号及条件，并接入[物品参数名称补充](item-catalog.md#参数名称补充)；属性名称和关联标签共用该结果，字段释义的待核验提示保留在关联依据中，item-read-model-v2描述扩展投影。

属性没有独立持久 Dataset、IndexedDB副本或通用跨版本机器Diff；这些不影响按历史Release读取同版关联。证据随代码版本发布，新增提交需要重新审阅。现有数据同步协议与批准规则不变。

## 验证

专项单元覆盖枚举取值、组合标记、未知值、无数据概念与排序、原始字段处置和单位继承，以及同义映射、未知字段隔离、官方变量展开、条件保留、已知公式、证据版本约束和游标串版拒绝。浏览流程覆盖片甲→护甲→片甲、公式输入、搜索／刷新、7.41e历史版本、中英和窄屏，以及驱散枚举筛选与技能往返；通过 `pnpm check --plan --files ...` 选择对应检查。

### 当前技能等级与常驻属性

`hero-abilities`维护与英雄等级相容的技能等级，`hero-ability-stats`仅把已注册的常驻自身加成传给属性投影。敌法师法术反制的魔抗按剩余伤害相乘；小小长大的护甲、攻击、攻速与移速使用当前级同版参数。未学习或未解锁技能不提供加成，天赋及神杖／魔晶沿用同一当前级投影。全等级数值只供比较；未适配被动、施法、叠层和命石效果提示未覆盖。注册表依据固定来源f4c457的对应英雄定义，仍保留引擎待核验边界。
