# 实体版本与语义变化

状态：2026-10-07 架构与7.41e／7.41f两版完整收录已实现。目标与后续完整验收见[实施任务](../work/entity-version-diff.md)。本合同替代 Catalog／ADR0001 中“产品仅查询 current head”的入口限制，原子 Catalog、来源和刷新门禁仍适用。

## 版本与完整状态

```mermaid
flowchart LR
  P[游戏补丁声明] --> R[Release 只读上下文]
  C[不可变 Catalog 全量状态] --> R
  M[独立地图 Dataset] --> R
  R --> U[URL release 参数与顶栏切换器]
  U --> Q[列表／详情／关系／搜索／缓存]
  A[绑定 Catalog 的独立资产] --> Q
  C --> S[实体稳定身份 + 该版属性／关系]
  M --> S
  S --> D[指定 from / to 的端点 Diff]
  D --> E[变化 + 来源 + 实现版本 + 未核对原因]
```

Release 是可查询的组合读上下文，不是新数据库 head，也不代表统一的客户端构建号。每个 Catalog 发布版本形成 `c:<dataset UUID>`；产品版本统一收录英雄、技能／天赋、命石、关系、本地化、单位定义与图片状态，以及有依据的地图对象／区域和资源。独立地图仍是来源Dataset；历史 `m:<collection ID>` URL在唯一完整Catalog对应时规范化到该Catalog入口，顶栏只显示完整版本。仅地图输入只供独立地图验证工作台使用，不作为产品版本。多个 Catalog 即使游戏补丁或客户端构建相同仍保持独立版本。

Catalog 的补丁标签复用固定 commit 与 steam.inf checksum 校验后的 change_log 解析；缺少证据为未知。地图补丁取 Collection 的声明。只有同补丁且恰有一份地图时关联两者；这表示补丁范围对应，**不认证两者客户端字节相同**。重复地图、补丁未知或地图缺失保留原因，绝不选择“最近”的另一份资源。地图与 Catalog 构建号分别返回。

顶栏在所有实体页面生效。无 `release` 的入口先重定向到当前默认的显式版本；未知、空或重复参数返回404。动态根布局不对整个页面套流式Suspense，保留真实404状态和生产开发入口隔离；URL客户端上下文在动态请求中读取。URL可分享恢复；不同标签页各自选择，浏览器不使用共享cookie或localStorage改变页面版本。旧地图链接进入对应完整版本；没有唯一对应关系时明确返回不可用。

Catalog head只选择默认入口，已发布历史版本不会被显式查询覆盖。公共入口仅暴露曾发布、非Red且审阅通过／无需审阅的版本；未发布候选继续走导入Review。列表API兼容原有固定Catalog／asset成对参数，并支持 `release`；两套参数冲突返回400，缺少图鉴覆盖返回410。

## Diff 合同

- `GET /api/releases` 返回收录版本及独立覆盖、默认入口；`GET /api/releases/diff?from=…&to=…` 返回结构化比较；`/changes?release=…&from=…` 是浏览页面。起点和终点均可在标题行独立选择已收录版本，终点使用release参数并与顶栏同步；缺省终点为最新默认Release，缺省起点为该Release在版本索引中紧邻的上一版，只有一版时两端相同；显式from／release始终优先，不因另一端切换而重置；按对象／变化类别及名称筛选，分组连续加载；前后值常显，原始字段和证据可展开。
- 两个**完整端点**直接比较，不累加中间事件；A→B→C中暂时新增后撤回、属性修改后还原不会出现在A→C最终差异。相邻及非相邻使用同一实现；同一版本重复计算稳定。
- 变化包含版本对、Diff实现版本、实体类型与key、entity/property/relation/mechanism/source_structure类别、增删改、JSON Pointer字段路径、前后值、双方来源以及待核对原因。数组作为有序属性整体比较；字典递归按字段比较。KV 对象先去除来源行号与唯一键顺序，重复键保留出现顺序；行号／路径仍保留在来源证据中。文件声明关系按英雄＋技能匹配，文件路径及声明行号不作为游戏关系变化。绑定ordinal可能保存来源行，统一去除；真实槽位仍由source_slot参与身份与状态比较。
- 未出现使用 `absent`，显式null使用 `value:null`，不会混淆。完整来源中实体不存在才判断新增／删除；来源缺失或身份规则不兼容为incomparable；部分来源仅比较已可靠匹配的状态，未匹配项列为unresolved。解析错误使请求失败，不能伪装成空快照。
- 全部覆盖可比且无变化为unchanged，有变化为changed；全部不可比为incomparable；有部分缺项、身份歧义、未知结构或实现变化为partial，同时保留已确认变化。
- 导入器、schema、单位适配器、地图导入器、经济算法版本分别记录在implementation；变化单独返回并使游戏归因需要复核，不能将Medota2实现升级当作游戏补丁。
- 原始未知结构保留内容和来源，结果列待核对；机制只报告已解析条件与效果，不声称具备完整引擎逻辑Diff。地图区域与完整脚本机制是下一阶段。

每个Catalog端点的13组业务查询通过一个已验证的可重复读只读事务顺序读取；来源、文件和技能数值按稳定键索引，保持顺序、重复来源及缺失状态。React请求缓存继续共享端点读取，不新增跨请求快照缓存。临时连接失败显示页内重试提示；不可用不能解释为零变化，重试保留release／from／筛选／语言。身份、权限、SQL及解析错误不能被此提示吞掉。

## 玩家可读变化与官方说明

变化页搜索输入即时更新，连续输入合并80ms筛选；同一比较端点内在客户端筛选已加载数据并用原生history同步URL，切换起始或终点版本才重新请求比较数据；输入法组词期间等待确认，清空及起始版本／终点版本／对象／变化筛选即时生效。移除比较按钮；保留光标、原始大小写与空格，查询端规范化；禁用系统补全、纠正、大写和拼写检查。搜索／筛选保留release与lang并重置连续列表；刷新及前进后退恢复URL条件。搜索框沿用其他图鉴的透明底色、左侧搜索图标及文字留白。数值排列说明移入标题信息图标提示；搜索与筛选整组放到标题行右侧，移除重复的版本箭头摘要，比较端点由相邻的起始版本与终点版本菜单表达。

变化页按英雄及其技能／天赋、物品／附魔组织，正文使用同端点中文名称、已知属性语义及“之前 → 之后”。每级数值保持顺序、去除小数尾零，百分比／秒采用同版数值条目的display_type、本地化或明确字段规则；天赋文本分别用前后端点的modifier数值解析。天赋换位保留移出／加入及各端点实际等级。数值的level_values／scalar_value及重复机制投影合并为一行，所有证据仍附在该行；筛选核对该行全部原始记录。

`src/presentation/entity-changes.ts`只负责无副作用展示。`src/server/services/release-changes.ts`复用请求内两个完整快照与经hash核验的同版本本地化，批量建立名称／归属索引，组合官方说明；不修改机器Diff API、发布指针或数据库。未知含义、解析差异和原始结构在统计旁的信息图标中保留，不替代为无变化。比较范围、全部未匹配记录及原文通过同一提示中的连续列表查看。

官方补丁说明是独立的说明来源。`src/data/patch-notes/7.41f.json`保存重排后的事实描述、来源URL／完整响应hash／导入时间、名称映射的固定提交和文件hash，以及已测量的物品定义差异。当前说明只绑定已审阅的7.41e／6918到7.41f／6944固定提交对，防止反向、同版、非相邻端点或同补丁其他构建误用。表格优先展示两端数值，官方文字在来源图标提示中保留；没有对应数值的说明另列。相同属性前缀或同节唯一相同端点的说明合并显示，不以这种展示匹配自动认证每个字段；未得到可读数值差异的说明明确待核对，行为修复提示需脚本／引擎验证。物品补充来自同提交原始KV报告，反向比较交换值与来源，官方说明仍只用于正向更新；未声称持久化了物品Catalog。

后续更新先获取并校验对应官方说明，固定来源URL／hash／时间，核对ID到同提交实体名称的唯一映射，生成有版本边界的说明数据；在完整版本收录后关联。不得在玩家请求时抓取外部最新内容，也不得给未知字段自动匹配相似官方描述。保持官方事实、实际数值与来源实现变化各自可追溯。

### 紧凑表格、实体与影响排序

- 按机制、英雄、物品、其他显示四个独立区段／表格；无可确认条目时保留空状态。英雄关联的技能、天赋及升级修正归该英雄，不能因为底层另有mechanism投影再重复列入机制；单位、无英雄归属技能及行为修复归其他。分类菜单使用同一归属规则。
- 列为全页连续序号、对象、改动项、详情、起始值、目标值、方向／幅度／差值、来源图标。英雄列原生rowSpan合并；相邻完整内容相同的格横纵合并，不因相同图标丢失不同链接或来源。表头吸顶，合并内容在表头下方吸顶且不越过所属单元格底部；方向、幅度与实际差值优先同行，差值列按clamp(230px,21vw,320px)分配，多等级过长时自然换行；实体图标随文字缩放、英雄头像适当放大，典型数值行约27px，长说明自然换行。对象与改动项按当前筛选结果的全部名称及行内图标实际宽度收紧，两列内容上限均200px，另计单元格左右共16px内距；长名称完整换行，表头宽度也计入。使用无链接／Tooltip／图片请求的轻量标签样本，按名称及图标种类去重；过滤／语言／字体变化重新测量，虚拟块滚动增减不改变列宽。前后值各按clamp(200px,16vw,280px)分配稳定列宽，内容上限260px；详情列吸收其余全部宽度。表格最小1200px，窄屏只在表格容器横向滚动，页面文档持续纵向滚动。
- `EntityPreview`是绑定版本的紧凑展示投影，`EntityReference`／`EntitySummaryCard`提供可全局复用的图标、名称、简述及少量关键数值；`EntityText`只匹配已解析实体的完整名称。英雄、技能、物品、单位图片各用对应端点资产版本；缺图保留可访问的类别图标。文字中的引用候选限制在当前变化相关实体及英雄，避免把“治疗”等一般词误认成无关技能。属性同义身份沿用属性模型。行内引用图标随当前字号缩放且不超过行高，避免撑高正文，规则见[语义UI](semantic-game-ui.md)。
- 来源、官方原文、原始字段、双方commit／路径、核验范围与排序解释只在图标／数值HoverTooltip中显示；支持键盘焦点、触摸点击、Escape及移入浮层。另一语言的本地化记录保留在原始资料，主表只显示当前语言。原文跨语言时标注source locale。
- 三类方向为增强、削弱、持平；同一条各等级有增有减归持平并标±。未知语义／行为修复／条件重构归持平的待判断状态，显示问号，不能将它解释成已确认没有影响。
- 幅度是各等级 `(新值−旧值)/abs(旧值)` 的均值，单值与多等级比较时广播单值；零基线且发生变化不伪造百分比，用“—”。正负号表达数值方向，增强／削弱另按语义判断。修正项复用现有升级计算，以两端条件生效后的实际数值计算幅度，提示内显示该计算基数；原始修正数值仍在主表及来源保留。
- 实际差值为同一有效端点的`终点−起点`，带数值正负号，独立于增强／削弱的收益方向。各等级逐级显示，相同差值合并一次；单值按既有规则广播。秒沿用显式单位，百分比属性差显示百分点；零基线仍显示实际差值。条件变化沿用impactBasis有效值；未知收益方向仍可显示已知数值差，文本、计量方式或等级结构不可比时为“—”，不编造数值。
- 排序是可审阅的影响优先级估算：已登记字段的收益方向、控制／冷却／资源／经济等权重与尺度共同计算，多等级绝对影响取平均；天赋条件乘0.6。护甲用至少10点、基础恢复至少每秒2点的比较尺度，避免小分母夸大基础值；图纸价格按所属整件物品价格作为排序基数。具体字段注册在`change-impact.ts`；不依据不确定字段名的模糊匹配自动判断。
- 组间按该组最大影响降序；每个对象内先按改动项稳定身份（类型与key，版本链接不拆分同一身份）聚合，同一改动项的全部行连续排列，不因方向不同被拆开；改动项之间按最大影响降序。每项内部按削弱→增强→持平分段，段内按单条影响降序，稳定key打破平分；同名不同身份不混合。以红／绿／灰浅底色和段首4px额外留白区分，不添加彩色边框或侧色条，影响列保留方向文字，颜色不是唯一提示；表格标题旁显示当前筛选结果的各类数量，空类省略。数值与详情合并不跨方向，对象／改动项身份仍可合并覆盖多段；搜索及方向筛选后重新计算对象和改动项最大值并保持同项连续。合并对象列意味着全页不是跨组逐行严格降序。该优先级不是胜率／整体英雄强度百分比，缺乏可比语义的行保留待判断，避免伪造精确收益。
- 由通用`GroupedTable`封装共享`useInfiniteList`本地适配器：按完整对象及横纵合并矩形规划原生tbody，同内容跨组相邻时共用虚拟块，整块懒挂载／等高回收，rowSpan不跨chunk；上7屏、下10屏预取。首组SSR可读，无分页，图标按浏览器惰性加载。数据是已加载的两个完整端点派生投影，虚拟化限制DOM，不冒充新增了远程分页API。

## 存储、导入与同步

复用不可变全量Catalog和地图包，不新增迁移或改写旧migration。未变化实体在新版完整快照中照常存在；旧记录与来源不删除。版本索引与Diff为派生只读投影，回退代码不需要回滚业务数据。

每次新版本先创建完整候选，准备英雄／技能资产、同提交单位定义与完整单位图片状态、双语本地化、命石／关系、同提交物品定义及完整图片，以及同补丁唯一地图及其资源／routing校验。已知地图客户端构建须与Catalog一致；历史未知构建保留未知。`inspectReleaseReadiness`统一核对；自动导入与显式提升都受此门禁约束，缺项候选不能成为默认版本。来源查找顺序为配置的固定worktree、本机固定commit缓存、配置外部输入，各读者继续核对精确commit与记录hash。

实际更新仍按[刷新门禁](../adr/0003-catalog-refresh-gates.md)生成候选、校验、审阅、提升；首次导入与资产准备见[导入手册](../operations/catalog-import.md)。公开历史浏览不意味着批准候选。下一次更新需要保留每个Catalog来源commit和匹配资产，不能覆盖旧来源或修改当前记录。

完整开发快照既有导出覆盖所有业务表记录、source_snapshots／source_snapshot_files及全部地图Collection；collectSources逐版本保存固定Git对象与运行时文件。派生索引与Diff随相同来源重建，无新增同步schema。跨机器一致性仍需在下一次真实多Catalog快照发布／消费时核验，当前只读检查不能代替这项验收。

缓存身份已包含Catalog＋asset＋语言＋环境；显式版本关闭current-head自动切换，搜索、语言、清空、详情跳转及预取均保留URL版本。未指定版本API仍支持读取head作为默认；版本化来源与图片各自沿用原有验证。
